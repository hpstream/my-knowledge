# 第 08 篇｜上线前最后检查表 + 上线后 24 小时要盯什么

> 适合人群：你的网站已经能打开，数据库接上了，邮件能发了，域名也接好了，现在准备真正对外发布  
> 目标：**把“临门一脚的疏忽”降到最低，让你上线后不至于慌。**

---

## 为什么还要有这篇？

因为很多人并不是不会部署，而是：

> **以为网站能打开，就等于可以上线了。**

但实际上，一个网站正式对外发布前，至少还要确认：

- 登录正常吗？
- 邮件能收到吗？
- 数据库真的在写远程库吗？
- 域名和 HTTPS 稳吗？
- 管理后台你自己能进吗？
- 用户点进来时有没有最基础的引导？

这篇就是给你一份：

> **最后上线前的总清单。**

你不要凭感觉发，照着一条条勾就行。

---

# 第 1 章：上线前你要检查的 5 个层面

上线前要检查的，不只是“页面能打开”。

你要按 5 层看：

1. **页面层** —— 首页、专题页、后台页能不能打开
2. **登录层** —— 邮箱验证码流程顺不顺
3. **数据层** —— 数据是不是写进远程数据库了
4. **域名层** —— 正式域名和 HTTPS 是否稳定
5. **运营层** —— 用户第一次进来会不会迷路

如果这 5 层都通过，你的网站就已经足够上线给第一批真实用户使用了。

---

# 第 2 章：上线前总清单（建议你逐项打勾）

## A. 页面检查

- [ ] 首页 `https://你的域名.com/` 能正常打开
- [ ] `/topics` 能正常打开
- [ ] 至少 3 篇专题能正常打开
- [ ] `/paths/vibecoding-getting-started` 能打开
- [ ] 任一 lesson 阅读页能打开
- [ ] 管理后台 `/admin` 你自己能进
- [ ] `/admin/articles`、`/admin/paths`、`/admin/feedback` 都能进

### 为什么要逐个点？

因为“首页能打开”不代表其他页没问题。

很多隐藏 bug 都在：
- 列表页正常，详情页 404
- 后台路由没锁权限
- 管理后台在生产环境缺环境变量

---

## B. 登录检查

- [ ] 点“登录 / 注册”会弹出邮箱登录模态
- [ ] 输入邮箱后，验证码邮件能收到
- [ ] 填验证码后能成功登录
- [ ] 刷新页面后登录态仍存在
- [ ] 退出登录后，再刷新确实是未登录状态
- [ ] 未登录用户点 lesson 页会被拦住，不会直接看到受保护内容

### 这里最容易漏的是什么？

**只测自己登录成功，不测退出和刷新。**

但用户真实使用时：
- 会刷新
- 会关浏览器再回来
- 会登出

所以这些都要测。

---

## C. 数据检查

- [ ] 注册一个新邮箱后，Neon 数据库里的 `User` 表多出一条
- [ ] 做完一篇小测后，`UserLessonProgress` 有记录
- [ ] 在后台新建文章后，`Article` 表里真有新数据
- [ ] 在后台新建路径后，`LearningPath` 表里真有新数据
- [ ] 提交读者反馈后，`ArticleFeedback` 表里真有新数据

### 为什么这一步必须做？

因为你要确认：

> **当前网站写入的是远程数据库，不是本地假数据。**

如果只看页面，不看库，很容易以为成功了，实际上线上根本没存进去。

---

## D. 域名与 HTTPS 检查

- [ ] 打开主域名，例如 `https://chaojigeti.com`
- [ ] 能正常显示小锁头（HTTPS）
- [ ] 如果你配了 `www`，那 `https://www.xxx.com` 也能打开
- [ ] 从手机 4G/5G 网络访问也能打开（不要只在同一 Wi-Fi 下试）
- [ ] 用无痕模式打开也正常

### 为什么要手机流量也试？

因为有些 DNS 缓存 / 本地网络问题，在你电脑上正常，不代表别人网络也正常。

手机流量更接近真实用户环境。

---

## E. 运营层检查

- [ ] 首页第一屏能让新用户看懂“这是干嘛的”
- [ ] 最新专题列表能让人知道“先看哪篇”
- [ ] 至少有一篇足够完整的专题，能让第一次来的用户得到结果
- [ ] 管理后台里你能自己快速找到文章、路径、反馈
- [ ] 读者反馈按钮可用

### 这一步为什么重要？

因为用户不会在意你技术架构多优雅。

他只在意：

> **我第一次进来，有没有看懂、有没有顺手、有没有得到帮助。**

---

# 第 3 章：上线当天最该做的 3 件事

如果你今天准备正式对外发出来，最优先做这 3 件事：

## 1. 自己完整走一遍“新用户第一次体验”

流程是：

```text
打开首页
→ 看专题
→ 登录
→ 收验证码
→ 进入内容
→ 完成一篇 lesson 或一篇 topic
→ 提交一次反馈
```

### 为什么这么做？

因为这能发现：
- 首次登录是不是顺
- 邮件能不能收到
- 用户进来后会不会迷路
- 最关键的“啊哈时刻”有没有发生

---

## 2. 让一个不懂技术的朋友帮你试

你别只自己试。

找一个：
- 不懂代码
- 没看你项目开发过程
- 最好从没见过你网站的人

让他在你旁边操作：

> 不要指导，先看他卡在哪里。

你会得到特别真实的反馈：
- 他第一眼看不懂什么
- 哪个按钮他犹豫了
- 哪个术语你以为简单，其实他完全不懂

这一步价值极高。

---

## 3. 准备一个“出问题时先看这里”的位置

比如：

- Neon 看数据
- Vercel 看部署日志
- Resend 看邮件发送记录
- 管理后台看反馈

你上线后最怕的不是出 bug，最怕的是：

> **出了问题，你连去哪里看都不知道。**

所以你要先在脑子里有这张图：

| 出问题现象 | 先看哪里 |
|---|---|
| 网站打不开 | Vercel |
| 登录后不记住 | 浏览器 Cookie / Session 表 |
| 收不到验证码 | Resend |
| 数据没保存 | Neon / Prisma Studio |
| 用户说文章有错 | `/admin/feedback` |

---

# 第 4 章：上线后 24 小时，重点盯什么？

你刚上线后的前 24 小时，不要继续疯狂加功能。先观察。

## 第一类：邮件有没有正常送达

看：
- 有没有人请求验证码
- 有没有人说“收不到邮件”
- Resend 的发送记录有没有失败

如果邮件出问题，用户连第一步都走不进来。

### 所以上线后前 24 小时，最先盯邮件。

---

## 第二类：数据库有没有正常写入

看：
- `User` 有没有新增
- `UserLessonProgress` 有没有新增
- `ArticleFeedback` 有没有新增

如果这些都没变化，而你知道有人在用，那就说明：

> 页面看起来能用，但后端数据没真正写进去。

---

## 第三类：用户最常卡在哪里

看：
- 他们最常反馈哪一步
- 他们最常从哪篇专题退出
- 他们进了首页之后有没有继续点进去

你现在还没接完整埋点系统没关系，先看：
- 反馈内容
- 真实聊天
- 朋友试用观察

就已经足够发现大问题。

---

## 第四类：后台你自己能不能维护得动

上线后的第一天，你自己去后台操作这些：

- [ ] 新建一篇文章
- [ ] 改一篇文章
- [ ] 新建一条路径
- [ ] 看反馈并标记已处理

如果你自己都觉得不好用，那以后你让别人加入写内容时，一定更麻烦。

你之前自己说过：

> “内容跟不上，可以让别人加入来写，所以写文章的后台要弄得好。”

这就意味着：

> **后台可维护性，本身就是产品质量的一部分。**

---

# 第 5 章：上线后不要急着做什么？

## 1. 不要一上线就加收费

你已经明确说了：

> 先做内容，先不收费。

我完全同意。

因为第一阶段最重要的是：
- 内容有没有价值
- 用户有没有真的跑通
- 你这套“现成方案 + 阅读 + 小测”是否成立

收费不是第一优先级。

---

## 2. 不要一有 bug 就大改结构

刚上线时出的小 bug 很正常。

比如：
- 某篇文章文案不清楚
- 某个按钮不够明显
- 某个反馈描述不够准确

先修小问题，别因为一两个 bug 就推翻整套方向。

---

## 3. 不要同时追求太多平台

你现在最需要验证的是：

> 这套产品模式本身有没有价值

而不是同时去搞：
- 微信登录
- 付费系统
- 多语言
- 小程序
- 移动 App

这些都可以以后做。

---

# 第 6 章：上线前的最终“傻瓜版”清单

如果你很忙，只想看最短版，那就照着这个逐项打勾：

## 上线前最后 10 条

- [ ] 首页能打开
- [ ] 至少 3 篇专题能打开
- [ ] 登录能用
- [ ] 验证码邮件能收到
- [ ] 数据写入 Neon 正常
- [ ] 后台你自己能登录进去
- [ ] 能在后台新建/编辑文章
- [ ] 域名能打开
- [ ] HTTPS 有锁头
- [ ] 让一个朋友完整试过一次

只要这 10 条都通过，你就可以发出来。

---

# 第 7 章：上线后 24 小时的最终“傻瓜版”清单

- [ ] 看 3 次邮箱验证码发送是否成功
- [ ] 看 3 次数据库新增是否正常
- [ ] 看有没有新的反馈
- [ ] 看自己后台操作是否顺手
- [ ] 记下用户最常问的 3 个问题

如果这些都正常，你就不是“演示 Demo”了，而是：

> **真的上线了。**

---

## 最后一句

真正的网站上线，不是“代码跑起来”那一刻。

而是：

> **用户能进来、能登录、能收到邮件、能读内容、你能维护后台，而且第一天没崩。**

当这些都成立时，你的网站才算真正活了。
