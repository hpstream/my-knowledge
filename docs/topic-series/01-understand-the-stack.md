# 第 01 篇｜你的网站要上线，到底要准备哪些东西？

> 适合人群：完全没做过网站上线、对服务器/数据库/域名/邮箱服务没有概念的人  
> 目标：**先搞懂全图，不再被一堆名词吓到**  
> 这篇不讲代码，只讲角色、关系和顺序。

---

## 你现在面对的真实问题，不是“不会写代码”

很多人以为自己做不出一个网站，是因为不会写代码。

但当你真的开始做时，你很快会发现：

> **卡住你的，往往不是代码，而是代码外面的那些东西。**

比如：
- 代码写好了，放哪儿运行？
- 数据存在哪儿？
- 域名去哪里买？
- 别人为什么打开不了？
- 邮箱验证码是谁发出去的？

所以你现在最需要的，不是先学“如何写一个登录组件”，而是先理解：

> **一个网站跑起来，到底由哪些角色组成。**

---

## 一张图看懂

你的网站一旦真正上线，背后至少有这 5 个角色：

```text
用户
 ↓
域名（比如 chaojigeti.com）
 ↓
Cloudflare（指路、加速、安全）
 ↓
Vercel（真正运行网站代码）
 ↓
Neon（存数据）

如果要发邮件：
Vercel 里的代码 → Resend → 用户邮箱
```

再加一个你最先接触的：

```text
你的电脑 → GitHub → Vercel
```

所以最完整的链路其实是：

```text
你本地写代码
 ↓
GitHub 存代码
 ↓
Vercel 运行代码
 ↓
Neon 存数据库
 ↓
Cloudflare 管域名 / 访问加速
 ↓
Resend 发邮件验证码
```

如果你只记住一句话：

> **GitHub 存代码，Vercel 跑网站，Neon 存数据，Cloudflare 管域名，Resend 发邮件。**

这篇就值了。

---

## 1. Git / GitHub 是什么？

先从它开始，因为：

> **后面所有服务几乎都建立在 GitHub 之上。**

### Git 是什么？

Git 是：

> **记录代码变化历史的工具。**

你可以把它理解成：

> 写代码时的“时间机器 + 存档系统”

它会记住：
- 你改了哪些文件
- 什么时候改的
- 之前那个版本是什么样
- 出问题时怎么退回去

### GitHub 是什么？

GitHub 是：

> **把 Git 管理的代码放到网上的仓库。**

也就是说：

- Git 在你电脑里工作
- GitHub 是代码的云端仓库

### 为什么它这么重要？

因为后面像 Vercel、Cloudflare 这种平台，都会默认问你：

> 你代码在哪个仓库？

没有 GitHub，你后面的部署、自动更新、多人协作都会很麻烦。

### 对非程序员怎么理解？

Git / GitHub 不是“程序员炫技工具”，它本质是：

> **代码世界里的网盘 + 版本历史 + 团队协作平台。**

---

## 2. Vercel 是什么？

Vercel 是：

> **把你 GitHub 上的代码变成一个真正能访问的网站。**

### 它解决什么问题？

如果不用 Vercel，你就得自己买服务器、装 Node、配 HTTPS、配部署流程。

这对小白来说太重了。

Vercel 帮你做了这些：
- 自动拉 GitHub 仓库
- 自动安装依赖
- 自动构建
- 自动生成线上网址
- 自动 HTTPS
- push 后自动重新部署

### 你可以把它理解成：

> **帮你开一家“自动营业”的网站店铺。**

你只负责把货（代码）放到 GitHub，Vercel 帮你把货摆上架。

---

## 3. Neon 是什么？

Neon 是：

> **一个托管在云上的 PostgreSQL 数据库。**

翻成人话：

> **给你一个长期记住数据的地方。**

比如你的网站要记住：
- 谁注册了
- 谁登录了
- 哪篇文章写了什么
- 哪条专题更新了
- 谁学到了第几课
- 谁提了反馈

这些都要存数据库。

### 为什么不是直接用 SQLite？

SQLite 很适合：
- 本地开发
- 临时实验
- 单机项目

但一旦你要上线，它的问题是：
- 它是本地文件
- 云平台不适合长期保存这类文件
- 多人 / 多请求并发不稳

所以你真正准备上线时，应该直接用：

> **Neon / Supabase 这种远程数据库**

这也是你这次最重要的产品洞察之一：

> **新手不应该先绕一圈学本地 SQLite，再切线上库。**
> **应该一开始就知道：最终网站的数据应该放在远程数据库。**

---

## 4. Cloudflare 是什么？

Cloudflare 不是服务器，也不是数据库。

它主要做三件事：

### 1）买域名
比如：
- `chaojigeti.com`
- `super-solo.cn`

### 2）让域名找到你的网站
也就是：

> 当别人访问你的域名时，Cloudflare 告诉浏览器：这个域名应该去找哪台服务器（比如 Vercel）。

### 3）加速和安全
它还会顺手帮你：
- CDN 加速
- HTTPS
- 基础安全防护

### 对小白怎么理解？

> **Cloudflare = 域名管理员 + 指路系统 + 加速器**

---

## 5. Resend 是什么？

Resend 是：

> **发邮件的服务。**

比如你的网站要做：
- 邮箱验证码登录
- 注册确认
- 找回密码

都需要发邮件。

你当然可以自己搭邮件服务器，但对新手来说完全没必要。

Resend 的价值就是：

> **让你用 API 发邮件，而不用自己学 SMTP 和邮件投递规则。**

对小白怎么理解：

> **Resend = 你网站的邮件快递员。**

---

## 6. 为什么不是一个平台全搞定？

很多人第一次接触时都会问：

> 为什么不能一个网站把这些事全做完？

答案是：因为每个平台都有自己最擅长的那一块。

| 平台 | 最擅长的事 |
|---|---|
| GitHub | 存代码 / 版本管理 |
| Vercel | 跑 Next.js 网站 |
| Neon | 提供 Postgres 数据库 |
| Cloudflare | 域名 / DNS / 加速 |
| Resend | 发邮件 |

它们不是“乱”，而是：

> **每家都只做自己最擅长的一块，结果组合起来反而更省心。**

---

## 7. 那我现在正确的顺序是什么？

先理解顺序，后面你就不会迷路。

### 第一步：准备账号
- GitHub
- Vercel
- Neon
- Cloudflare
- Resend

### 第二步：把代码放到 GitHub

### 第三步：让 Vercel 先把网站跑起来
先拿到一个：

```text
xxx.vercel.app
```

### 第四步：把数据库接到 Neon

### 第五步：把邮件接到 Resend

### 第六步：最后买域名，用 Cloudflare 接上

为什么这个顺序最适合小白？

因为它遵循一个原则：

> **一次只解决一层问题。**

而不是一上来就同时折腾：
- 部署
- 数据库
- 域名
- 邮件
- 备案

那样几乎一定崩。

---

## 8. 你现在已经不应该再困惑的点

看完这篇，你至少应该能区分：

### GitHub ≠ Vercel
- GitHub 存代码
- Vercel 跑代码

### Vercel ≠ Neon
- Vercel 运行网站
- Neon 存数据

### Cloudflare ≠ 服务器
- Cloudflare 是域名和指路系统
- 它不是你的数据库

### Resend ≠ 登录系统
- Resend 只是帮你发邮件
- 真正的登录逻辑还是你网站代码写出来的

---

## 9. 这篇文章结束后，你下一步应该看什么？

按顺序建议是：

### 1. 《第 02 篇：注册 GitHub、Vercel、Neon、Cloudflare、Resend》
先把所有账号准备好。

### 2. 《第 03 篇：把本地项目推到 GitHub，然后让 Vercel 第一次跑起来》
第一次真正部署。

### 3. 《第 04 篇：把数据库接到 Neon 上》
让网站真正能保存数据。

---

## 最后一句

你不是不会做网站。

你只是以前没人先告诉你：

> **一个网站上线，不是一个技术点，而是 5 个角色一起协作。**

只要你把这 5 个角色分清楚，后面的所有操作都会清楚很多。
