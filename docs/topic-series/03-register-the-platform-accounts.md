# 第 03 篇｜注册 Vercel、Neon、Cloudflare、Resend：你到底得到了什么？

> 适合人群：已经有 GitHub 账号，但不理解为什么还要再注册 4 个平台的人  
> 目标：**不是只知道“去注册”，而是知道每注册一个账号，你后面上线链路里会少掉哪个坑。**

---

## 你现在为什么还要再注册 4 个平台？

因为：

> GitHub 只解决了“代码放哪儿”的问题。

但一个网站真正要跑起来，还有 4 件事要分别解决：

| 问题 | 负责的服务 |
|---|---|
| 代码放哪儿 | GitHub |
| 网站在哪儿运行 | Vercel |
| 数据存哪儿 | Neon |
| 域名在哪儿买、怎么指过去 | Cloudflare |
| 邮件验证码谁来发 | Resend |

所以你不是“为了注册而注册”，而是在给你的网站准备 4 个角色。

---

# 第 1 节：注册 Vercel

## Vercel 是干嘛的？

一句话：

> **Vercel 负责把你 GitHub 上的代码变成一个别人能访问的网站。**

你可以把它理解成：

> **你网站真正营业的门店。**

如果没有 Vercel（或者同类平台），你就得自己买服务器、自己装 Node、自己配 HTTPS、自己处理自动更新。

对小白来说，这一步最容易把人劝退。

所以 Vercel 的意义是：

> **把“运维服务器”这件事先省掉。**

## 怎么注册？

网址：

> <https://vercel.com>

### 推荐登录方式

直接点：

> **Continue with GitHub**

### 为什么推荐 GitHub 登录？

因为后面你要让 Vercel 读取 GitHub 仓库。

早点用 GitHub 授权登录，相当于先把：

> “代码仓库 ↔ 部署平台”

这条线打通。

### 你点完之后会发生什么？

GitHub 会弹一个授权页，问你：

> “要不要允许 Vercel 访问你的仓库？”

点同意。

### 你最后得到什么？

- 一个 Vercel 账号
- 它已经和 GitHub 打通

这意味着：

> 以后你只要 push 代码，Vercel 就可以自动重新部署。

---

# 第 2 节：注册 Neon

## Neon 是干嘛的？

一句话：

> **Neon 是给你远程数据库的地方。**

### 为什么它重要？

你的网站不是只有页面，还要记东西：

- 用户
- 文章
- 路径
- 学习进度
- 反馈

这些数据不能只存在你本地电脑里。

所以 Neon 的作用是：

> **让你的网站即使部署到线上，也有一个稳定的地方保存数据。**

### 为什么我们不推荐继续用 SQLite 上线？

因为 SQLite 更像：

> 你电脑里的一个小文件数据库

它适合本地开发，但不适合长期在线上运行。

所以你真正准备上线的时候，应该直接走：

> **Neon（PostgreSQL）**

这会省掉很多绕路。

## 怎么注册？

网址：

> <https://neon.tech>

### 推荐登录方式

继续点：

> **Continue with GitHub**

### 为什么还推荐 GitHub 登录？

因为统一、少一个密码，而且你后面所有开发基础设施都尽量围绕 GitHub 整合，会省很多心智负担。

### 注册后要做什么？

创建一个新的 Project。

比如名字可以叫：

```text
super-solo-prod
```

创建好后，你会得到一个最重要的东西：

> **数据库连接串（connection string）**

类似：

```text
postgresql://用户名:密码@主机名/数据库名?sslmode=require
```

这串东西以后会放进 `.env`：

```env
DATABASE_URL=postgresql://...
```

### 你最后得到什么？

- 一个线上数据库项目
- 一串连接地址

这意味着：

> 你的网站以后终于有了真正的“远程大脑”。

# 第 3 节：注册 Cloudflare

## Cloudflare 是干嘛的？

Cloudflare 最核心负责的是：

1. **买域名**
2. **管理域名解析（DNS）**
3. **让网站访问更稳定、更快**

它不是数据库，也不是你的网站运行环境。

你可以把它理解成：

> **你网站的门牌号管理员 + 导航系统 + 保安。**

## 为什么必须有它？

因为你以后一定不想用：

```text
xxx.vercel.app
```

而是想用你自己的域名，比如：

```text
chaojigeti.com
```

域名在哪里买？
域名怎么让它指到 Vercel？
谁帮你管这些记录？

Cloudflare 就负责这些。

## 怎么注册？

网址：

> <https://cloudflare.com>

用邮箱注册即可。

### 今天注册完需要立刻买域名吗？

不用。

今天先把账号开好就行。

等你的网站先在 Vercel 上跑起来，再买域名最合理。

### 你最后得到什么？

- 一个 Cloudflare 账号

这意味着：

> 以后你要买域名、配域名指向时，不会临时再卡住。

---

# 第 4 节：注册 Resend

## Resend 是干嘛的？

Resend 的作用非常单纯：

> **帮你的网站发邮件。**

你现在项目里已经有：

- 邮箱验证码登录

这意味着以后线上必须能发真实邮件。

如果没有 Resend（或者类似服务），你的网站就只能：

- 本地把验证码打印到终端
- 线上用户根本收不到验证码

所以 Resend 负责的是：

> **让你的登录真正能被用户使用。**

## 怎么注册？

网址：

> <https://resend.com>

### 推荐方式

继续用 GitHub 登录。

### 今天要不要立刻验证域名？

也不用。

因为验证发件域名这一步，依赖你先有正式域名。

而你域名还没买。

所以今天只需要做到：

- 账号注册成功
- 能进 Dashboard

### 你最后得到什么？

- 一个以后可以发验证码邮件的服务账号

这意味着：

> 你的登录系统已经有了“快递员”，只是还没正式派单。

---

# 第 5 节：为什么这 4 个平台都推荐用 GitHub 登录？

你会发现，我一直在建议：

- Vercel 用 GitHub 登录
- Neon 用 GitHub 登录
- Resend 也可以用 GitHub 登录

原因很简单：

## 1. 少记密码
少一个平台，就少一套账号密码。

## 2. 管理统一
以后这些服务都围绕同一个“开发者身份”来工作。

## 3. 授权链路更顺
比如 Vercel 本来就要读 GitHub 仓库，用 GitHub 登录最自然。

## 4. 你以后如果让别人协作，也更好解释

> “我们这条产品的技术基础设施，全部围绕 GitHub 这一个开发身份来搭。”

对小白来说，这个统一非常重要。

---

# 第 6 节：注册完这些账号后，你实际上得到了什么？

很多教程只会告诉你：

> “先去注册这个、再去注册那个。”

但不会告诉你：

> 注册完以后，你到底解决了什么问题。

我把它写清楚：

| 平台 | 注册后你真正得到的东西 | 它解决什么问题 |
|---|---|---|
| GitHub | 一个代码仓库账号 | 代码存哪儿 |
| Vercel | 一个部署账号，且和 GitHub 打通 | 网站在哪儿运行 |
| Neon | 一个数据库项目 + 连接串 | 数据存哪儿 |
| Cloudflare | 一个域名 / DNS 管理账号 | 域名在哪里买、怎么指路 |
| Resend | 一个邮件发送账号 | 邮箱验证码谁来发 |

这张表你以后可以反复看。

---

# 第 7 节：今天完成的标志是什么？

你今天不需要部署，也不需要 push 代码。

今天完成的标志是：

- [ ] GitHub 账号注册完成
- [ ] Vercel 账号注册完成，并通过 GitHub 登录
- [ ] Neon 账号注册完成，并创建了第一个 Project
- [ ] 你手里保存好了 Neon 的连接串
- [ ] Cloudflare 账号注册完成
- [ ] Resend 账号注册完成

如果这几项都完成，说明：

> **你已经把后面所有步骤会卡住的账号问题，提前清掉了。**

---

# 第 8 节：最容易卡住的地方（提前给你打预防针）

## 卡点 1：我在 Vercel 授权 GitHub 时不敢点

别怕。

那只是：

> 允许 Vercel 读取你的 GitHub 仓库来部署网站。

不是公开代码，也不是把账号交出去。

如果你仓库是 Private，别人依然看不到。

---

## 卡点 2：Neon 给的连接串看不懂

这很正常。

你现在不用完全理解它，只需要知道：

> 这是你的应用进入数据库的钥匙。

以后放到 `.env` 里，它就开始发挥作用了。

---

## 卡点 3：Cloudflare 注册完后我不知道点哪里

也没关系。

Cloudflare 最重要的操作（买域名、配 DNS）要等后面真正接域名时再做。

今天只是：

> 先把账号开好。

---

## 卡点 4：Resend 里为什么还有 Domain 这些词

因为发邮件最终要从你的域名发出去，比如：

```text
noreply@你的域名.com
```

但今天你还没有域名，所以：

> 先忽略这些高级配置。

---

# 第 9 节：今天结束后，你下一步该干什么？

做完这篇后，最自然的下一步就是：

## 《第 03 篇：把本地项目推到 GitHub，然后让 Vercel 第一次跑起来》

也就是：
- `git init`
- `git add`
- `git commit`
- GitHub 新建仓库
- push 到 GitHub
- 在 Vercel 上导入仓库
- 第一次拿到 `xxx.vercel.app`

这是你真正第一次“让别人看到你的网站”。

---

## 最后一句

今天你注册的不是一堆乱七八糟的平台。

你其实是在给你的网站搭出 4 个关键角色：

- 跑代码的
- 存数据的
- 管域名的
- 发邮件的

等这些角色都就位，后面的上线就只是把它们串起来。
