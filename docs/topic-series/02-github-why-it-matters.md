# 第 02 篇｜先注册 GitHub：它为什么是最重要的入口？

> 适合人群：还没有 GitHub 账号，或者有账号但完全不知道它到底是干嘛的人  
> 目标：**你不只是注册一个账号，而是明白为什么后面所有服务都要围着 GitHub 转**

---

## 为什么我把 GitHub 单独拎出来讲？

因为对真正的小白来说，GitHub 不是“程序员社区”，而是：

> **后面所有自动部署、版本管理、多人协作的起点。**

你如果没有 GitHub，后面的这些事情都会变得更麻烦：

- Vercel 没法直接自动部署
- 代码没有可靠备份
- 改错了没法回退
- 想找别人协作很困难

所以它不是“可选项”，而是：

> **第一个必须准备好的基础设施账号。**

---

## Git 和 GitHub 到底是什么关系？

### Git
Git 是：

> **你电脑里记录代码变化历史的工具**

### GitHub
GitHub 是：

> **把 Git 记录的代码历史上传到网上的仓库**

最简单的理解是：

| 名词 | 白话 |
|---|---|
| Git | 你本地电脑里的“版本记录器” |
| GitHub | 互联网里的“代码仓库” |

所以别把这两个词混了：

- Git 不是网站
- GitHub 不是编译器
- GitHub 也不是部署平台

它的核心价值就是：

> **帮你把代码好好存起来，并让别的平台（比如 Vercel）能读到它。**

---

## 如果你没有 GitHub，会卡在哪里？

假设你没有 GitHub，而是只在本地电脑里写代码。

那会出现这些问题：

### 1. 代码只在你自己电脑上
你电脑坏了 / 删了 / 重装系统，项目可能就没了。

### 2. 没有清晰版本
你今天改了一堆代码，明天网站炸了，你不知道怎么退回昨天那个版本。

### 3. 不好部署
Vercel、Cloudflare Pages 这种平台都喜欢从 GitHub 直接拉代码。
如果没有 GitHub，你就得走更麻烦的上传或 CLI 流程。

### 4. 没法跟别人协作
别人帮你看问题、改代码、帮你写内容时，都需要一个共同的代码仓库。

所以：

> **GitHub 解决的不是“会不会写代码”，而是“代码有没有一个可靠的家”。**

---

## GitHub 账号怎么注册？

网址：

> <https://github.com>

### 第一步：点 Sign Up
你会看到页面右上角有：

- **Sign up**
- 或 **Create account**

这一步就是在创建你的 GitHub 身份。

### 第二步：填 3 个核心信息
一般会要你填：

1. **Email** —— 你的邮箱
2. **Password** —— 你的密码
3. **Username** —— 用户名

---

## 用户名该怎么想？

很多人第一次就卡在这里：

> “这个用户名是不是以后都改不了了？”

可以改，但一开始尽量别太随意。

### 你应该怎么选？

选一个：
- 以后不尴尬
- 你自己能接受别人看到
- 不要太长

比如：

- `hamster-dev`
- `hpstream`
- `chaojigeti-dev`

都比：

- `abc123456789`
- `qweasdzxc777`

这种好得多。

### 为什么？

因为以后你的仓库网址会长这样：

```text
https://github.com/你的用户名/仓库名
```

所以用户名就是你对外的“代码身份”。

---

## 邮箱验证为什么必须做？

GitHub 会给你发一封验证邮件。

你要去邮箱里点那个链接。

### 这一步解决什么问题？

- 证明这个邮箱真的是你的
- 以后忘密码可以找回
- 安全提醒能收到
- 某些操作没有验证邮箱会被限制

所以：

> **别跳过，立刻验证。**

---

## 注册完后建议立刻做的 2 件事

### 1. 开启双重验证（2FA）
路径通常在：

```text
头像 → Settings → Password and authentication
```

你会看到：

> Two-factor authentication

建议打开。

### 为什么？

GitHub 太重要了。
如果账号被盗：
- 代码仓库会丢
- 别人可以伪造你提交代码
- 部署链路都可能受影响

开启后，即使密码泄露，别人也进不去。

---

### 2. 先不用碰一堆高级功能
GitHub 里会有很多你现在看不懂的东西：

- Issues
- Pull Requests
- Actions
- Projects
- Discussions
- Packages

这些你现在都可以忽略。

你先只记住最关键的 3 个：

- **Repositories** = 代码仓库
- **Settings** = 设置
- **Code** = 代码页面

这就够了。

---

## GitHub 对你这个项目，后面具体起什么作用？

以你当前的 `my-knowledge / 超级个体` 为例：

后面我们会做这件事：

```text
你的本地项目
  ↓
git init / git add / git commit
  ↓
push 到 GitHub
  ↓
Vercel 读取 GitHub 仓库
  ↓
把网站部署到线上
```

所以 GitHub 在你项目里的角色是：

> **代码入口站**

它不是最终网站，也不是数据库，但它是：

> **Vercel 看见你代码的唯一正规入口。**

## 这一步完成后，你应该得到什么？

做完今天这篇的目标后，你应该有：

- [ ] 一个能正常登录的 GitHub 账号
- [ ] 一个完成邮箱验证的账号
- [ ] 一个你自己认可的用户名
- [ ] 最好已经开了双重验证

如果这些都做到，你就完成了第一层基础准备。
