# 第 06 篇｜把邮箱验证码从“终端打印”改成真实邮件（Resend）

> 适合人群：你的网站已经能跑、数据库也连上了，但用户还收不到真正的验证码邮件  
> 目标：**让登录验证码从“开发阶段的终端输出”切换成“生产环境真的能发邮件”**  
> 前提：你已经完成了第 05 篇，网站数据库已接到 Neon。

---

## 先说清楚：你现在的邮件系统处于什么状态？

你当前项目里，开发环境默认是：

```env
MAIL_DRIVER=console
```

它的意思是：

> 用户请求验证码时，系统不会真的发邮件，
> 而是把验证码直接打印到运行 `pnpm dev` 的终端里。

### 这对开发很方便
因为你本地测试时：
- 不用注册邮件服务
- 不用浪费额度
- 不会把测试验证码发到真实邮箱

### 但线上绝对不行
因为线上用户看不到你的终端。

所以一旦你准备让别人真正登录，你必须把邮件发出去。

这就是 Resend 出场的原因。

---

## 第 1 章：Resend 是干嘛的？

一句话：

> **Resend 是帮你发邮件的服务。**

它负责：
- 接收你程序发出的“请给这个邮箱发验证码”请求
- 替你把邮件投递出去
- 帮你处理基础的送达问题

你不用自己搭 SMTP 服务器，也不用自己研究垃圾邮件规则。

这就是它对新手最有价值的地方：

> **你只管告诉它“往谁发什么”，它负责把邮件送出去。**

---

## 第 2 章：为什么不是继续用“终端打印验证码”？

因为“终端打印”只适合开发时你自己测试。

### 本地阶段：没问题
你开着 `pnpm dev`，看终端，复制验证码，回到浏览器填进去。

### 线上阶段：完全不行
线上用户：
- 不可能看到你的服务器终端
- 也不可能 SSH 到你的部署环境里复制验证码

所以：

> **终端打印验证码只是“开发假装发邮件”的办法。**
> **真正上线必须换成邮件服务。**

---

## 第 3 章：先搞懂“域名验证”是怎么回事

这里是小白最容易困惑的一步。

### 你可能会问：

> “我不是已经注册了 Resend 账号了吗？为什么还不能直接发邮件？”

因为如果任何人注册完就能随便伪造发件人，世界就乱了。

举个例子：

如果没有验证机制，别人就可以在 Resend 里直接写：

```text
from: support@alipay.com
```

然后冒充支付宝发邮件。

所以邮件服务商必须确认：

> **你真的拥有这个域名。**

### 这一步解决什么问题？

它在证明：

> “你确实有权从 `noreply@你的域名.com` 这个地址发邮件。”

这就是“域名验证”。

---

## 第 4 章：在 Resend 里注册并拿 API Key

### 第一步：打开 Resend

网址：

> <https://resend.com>

登录你之前注册的账号。

### 第二步：创建 API Key

进入 Dashboard 后，通常会看到：

- **API Keys**
- 或者 **Create API Key**

点进去，创建一个 Key。

### 这一步的意义

这个 API Key 就是：

> **你的网站调用 Resend 发邮件时用的钥匙。**

以后会放进环境变量里，例如：

```env
RESEND_API_KEY=re_xxxxxxxx
```

### 注意

和数据库连接串一样：

> **不要随便把它截图发出去。**

它是能直接调用你邮件额度的。

---

## 第 5 章：为什么还要验证域名？

你注册完 Resend 账号、拿到 API Key 后，还差最关键一步：

> **告诉 Resend：我有这个域名，我有资格从这个域名发邮件。**

### 举例

如果你的正式域名以后是：

```text
chaojigeti.com
```

那你希望验证码邮件从：

```text
noreply@chaojigeti.com
```

发出去。

Resend 不会凭你一句话就相信你拥有这个域名。

所以你必须在 Resend 里添加域名，然后它会让你去 DNS（通常是 Cloudflare）里加几条记录。

这一步本质上是在证明：

> 这个域名的 DNS 你能控制，所以你真的是域名所有者。

---

## 第 6 章：在 Resend 里验证域名

### 第一步：打开 Domains

在 Resend Dashboard 找：

- **Domains**
- 或 **Add Domain**

### 第二步：输入你的域名

比如：

```text
chaojigeti.com
```

### 第三步：Resend 会给你几条 DNS 记录

通常包括：
- SPF
- DKIM
- 有时还有 DMARC / MX

你不用现在理解这些缩写的含义。

你只需要知道：

> **这些记录是为了证明这个域名允许 Resend 代你发邮件。**

### 第四步：去 Cloudflare 添加这些记录

打开你的 Cloudflare：

- 找到你的域名
- 进入 **DNS**
- 按 Resend 给的内容，一条一条添加

### 第五步：等 Resend 验证成功

通常 5-10 分钟左右。

成功后你会看到类似：

```text
Verified
```

这就说明：

> 你的网站以后可以合法地从这个域名发邮件了。

---

## 第 7 章：很多人会在这里卡住的两个点

### 卡点 1：Cloudflare 里的“橙色云朵”

如果你用的是 Cloudflare，加 DNS 记录时有一个常见坑：

> 某些邮件相关记录不能走 Cloudflare 代理（橙色云）

简单记法：

> **邮件相关记录尽量用 DNS only（灰云）**

否则 Resend 可能一直验证不过。

### 卡点 2：我明明加了记录，为什么还显示 Pending？

因为 DNS 生效不是绝对实时的。

一般等：
- 1 分钟
- 5 分钟
- 最多十几分钟

再回来点刷新。

只要记录没填错，大多数时候都能过。

---

## 第 8 章：你当前项目里，最终要配哪些环境变量？

一旦你要把验证码切成真实邮件，最关键的是这几条：

```env
MAIL_DRIVER="resend"
RESEND_API_KEY="re_你的key"
MAIL_FROM="noreply@你的域名.com"
```

### 它们分别是什么意思？

#### `MAIL_DRIVER`
告诉系统：

> 现在不要再把验证码打印到终端，改成走 Resend 发邮件

#### `RESEND_API_KEY`
告诉系统：

> 用这把钥匙去调用 Resend API

#### `MAIL_FROM`
告诉系统：

> 验证码邮件看起来是从哪个邮箱地址发出来的

这个地址必须属于你已经在 Resend 验证过的域名。

比如：

```text
noreply@chaojigeti.com
```

---

## 第 9 章：这些环境变量放在哪里？

### 本地开发
如果你想在本地先试真发邮件，可以放到：

```text
.env
```

或：

```text
.env.local
```

比如：

```env
MAIL_DRIVER="resend"
RESEND_API_KEY="re_xxxxx"
MAIL_FROM="noreply@你的域名.com"
```

### 线上部署（Vercel）
去：

```text
Vercel 项目
→ Settings
→ Environment Variables
```

把同样三条配进去。

### 注意

你本地 `.env` 改了，**Vercel 不会自动同步**。

所以：

> 本地和 Vercel 后台，两边都要配。

## 第 10 章：怎么让你现在的代码切换到 Resend？

你当前项目已经有：

```ts
src/lib/auth/email.ts
```

开发模式现在是 `console` 输出。

真正上线时，你有两种选择：

### 方式 A：让 AI 帮你把 `email.ts` 扩成多驱动
你可以给 AI 这样的 prompt：

```text
请扩展我项目里的 src/lib/auth/email.ts。
要求：

1. 现有 console driver 保留
2. 新增 resend driver
3. 当 process.env.MAIL_DRIVER === 'resend' 时：
   - 用 fetch 调用 https://api.resend.com/emails
   - Authorization: Bearer ${process.env.RESEND_API_KEY}
   - from: process.env.MAIL_FROM
   - to: 用户邮箱
   - subject / text 保持现有 buildLoginCodeEmail() 逻辑
4. 失败时抛出错误，让 API 路由返回 500
5. 代码要完整可运行，不要用 Resend SDK，直接用 fetch
```

### 方式 B：自己手动加
如果你后面需要，我也可以直接帮你把项目改成 Resend 版本。

## 第 11 章：怎么验证已经成功？

### 本地验证
1. 启动项目：

```bash
pnpm dev
```

2. 在登录弹框里输入一个你能收到的真实邮箱
3. 点发送验证码
4. 去邮箱看：
   - 有没有收到
   - 发件人是不是你配置的 `MAIL_FROM`
   - 验证码是不是 6 位数字

### Vercel 验证
1. 去线上网站
2. 输入你的邮箱
3. 看邮箱
4. 能收到 = 成功

## 第 12 章：最常见的报错是什么？

### 报错 1：发邮件 401 / 403
这通常是：
- `RESEND_API_KEY` 错了
- 没配置到 Vercel

### 报错 2：发件邮箱不合法
这通常是：
- `MAIL_FROM` 不属于已验证域名

### 报错 3：一直 Pending
这通常是：
- DNS 记录没填对
- Cloudflare 代理没关
- 还没等够时间

做到这些，说明：

> **你的登录系统已经从“开发专用假邮件”变成了“线上真实可用邮件”。**
