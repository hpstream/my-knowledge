# 第 10 篇｜QQ 邮箱 SMTP 晚上突然不发邮件了，怎么排查？

> 适合人群：白天还能正常发，晚上突然没人收到验证码的人
> 目标：**5 步定位是哪一环卡住的，并知道怎么绕过**
> 前提：你已经按 [《第 09 篇 QQ 邮箱 SMTP 接入》](./09-qq-mail-smtp-for-testing.md) 跑通过 SMTP

---

## 先说结论

你晚上不发邮件，**99% 是下面三种里的一种**：

1. **当天发太多了，触发了 QQ 的「日发件配额」**（最常见，普通 QQ 邮箱免费账户大概 50 封/天，重置时间是北京时间 0:00）
2. **触发了 QQ 反垃圾风控，被临时限流**（短时间内对同一收件人重复发、或对很多陌生收件人短时间发）
3. **授权码被 QQ 失效了**（你换过设备登录、改过密码、或 QQ 那边主动撤销）

你看完这篇就能区分到底是哪一种。

---

## 1. 这个站点现在的发件链路长什么样？

回顾一下你的项目（`src/lib/auth/email.ts`）：

```ts
// 用户点 "发送验证码"
// ↓
// /api/auth/email/request-code 路由
// ↓
// sendEmail({ to, subject, text })
// ↓
// MAIL_DRIVER=smtp 时走 sendViaSmtp(...)
// ↓
// nodemailer.createTransport({ host: smtp.qq.com, port: 465, secure: true })
// ↓
// QQ 邮箱服务器（smtp.qq.com）
// ↓
// 收件人的邮箱服务器
// ↓
// 收件人的收件箱
```

**任何一环卡住，最终结果都是「收不到邮件」。** 排查就是顺着这条链路一段一段查。

---

## 2. 5 步排查法（按顺序做）

### Step 1：先看你自己的服务端日志

在你跑 `pnpm dev` 或线上服务的终端里，看有没有抛错。

**情况 A — 完全没看到任何日志**：
说明请求根本没进到 `sendEmail`，可能前端按钮被前面的频率限制挡掉了。
检查：浏览器 DevTools 的 Network 面板，看 `/api/auth/email/request-code` 返回的是什么。

**情况 B — 看到了日志，但 nodemailer 抛了错**：
错误信息通常长这样：

```
Error: Invalid login: 535 Login Fail. Please enter your authorization code to login.
```

```
Error: Connection timeout
```

```
Error: 554 DT:SPM ... QQ 邮件反垃圾系统
```

把错误信息按下面表对一下：

| 错误关键字 | 意思 | 怎么处理 |
|---|---|---|
| `535 Login Fail` / `Authentication failed` | 授权码错了或失效了 | 去 [Step 3](#step-3重新生成授权码) 重新生成 |
| `554 DT:SPM` 或 `RTR:BL` 等 | 被 QQ 反垃圾系统拦了 | 去 [Step 4](#step-4确认是不是被反垃圾限流) |
| `Connection timeout` / `ECONNREFUSED` | 网络层连不上 smtp.qq.com | 看本地网络/防火墙是否封了 465 端口 |
| `Daily user sending quota exceeded` | 当天发件配额用完了 | 去 [Step 5](#step-5确认是不是日配额用完) |

**情况 C — 日志显示「发送成功」**：
那就跳到 [Step 2](#step-2登录-qq-邮箱看已发送文件夹)。

---

### Step 2：登录 QQ 邮箱看「已发送」文件夹

这一步**最容易被忽略，但是判断价值最高**。

打开 [mail.qq.com](https://mail.qq.com)，登录你那个发件 QQ 邮箱（就是 `SMTP_USER` 对应的那个），点左侧「已发送」。

- **如果看得到刚才那封验证码邮件** → 你的程序没问题，QQ 也接受了，问题在「收件人那边」。
  跳到 [Step 6](#step-6收件人侧检查)。
- **如果「已发送」里根本找不到这封邮件** → QQ 在它自己服务器层面就拒收了。
  最大可能是反垃圾限流或日配额。跳到 [Step 4](#step-4确认是不是被反垃圾限流) / [Step 5](#step-5确认是不是日配额用完)。

> 👉 这里需要的是你能动手验证的判断步骤，QQ 反垃圾系统的内部算法属于运营层面的内容，可以搜索 QQ 邮箱官方反垃圾政策学习，这里不展开讲解。

---

### Step 3：重新生成授权码

> 触发场景：错误日志里有 `535 Login Fail` / 你最近改过 QQ 密码 / 你最近在新设备上登录过 QQ 邮箱。

操作步骤：

1. 浏览器登录 [mail.qq.com](https://mail.qq.com)
2. 顶部「**设置**」→「**账户**」
3. 滚动到「**POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV 服务**」
4. 找到「**生成授权码**」按钮，点它（旧的会同时失效）
5. 按提示用手机 QQ 扫码 / 短信验证
6. **复制新的 16 位授权码**

把新授权码替换到你的环境变量里：

```env
# .env.local 或线上环境
MAIL_DRIVER=smtp
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=你的qq号@qq.com
SMTP_PASS=新生成的16位授权码
MAIL_FROM=你的qq号@qq.com
```

⚠️ **`SMTP_PASS` 永远填授权码，不是 QQ 密码**。

重启服务再发一次：

```bash
pnpm dev
# 触发一次登录验证码
```

如果还报 `535`，说明你复制的时候带了空格或换行，重新复制一次。

---

### Step 4：确认是不是被反垃圾限流

> 触发场景：错误日志里有 `554 DT:SPM` / `RTR:BL` / `MAILBOX UNAVAILABLE` / Step 2 看「已发送」里没有那封邮件。

QQ 的反垃圾系统对**短时间高频发件**特别敏感，尤其是：

- 1 分钟内对同一个收件人发了好几次
- 几个小时内对几十个不同的陌生地址发件
- 收件人邮箱地址明显是临时邮箱（10minutemail 之类）

**怎么确认**：

- 等 30~60 分钟，对**另一个**邮箱（不要是你刚才一直发的那个）再发一次。能发出去 → 是临时限流，对那一个收件人的限流通常 1~2 小时解除。
- 如果对任何收件人都发不出去 → 风控级别升高了，可能要等到第二天 0:00 后才解除。

**怎么避开**：

- 前台已经有 60 秒倒计时（`LoginModal.tsx` 里的 `resendIn`），是对的。**不要把这个数字调小**。
- 如果是给一批陌生用户群发，**别用 QQ 邮箱**。生产场景该上 Resend / SendGrid。

---

### Step 5：确认是不是日配额用完

> 触发场景：**晚上失败**这一现象本身就是这个的高度提示。免费 QQ 邮箱普通账户日发件上限大约 **50 封**（VIP 会高一些，但官方从不公开精确数字）。

最快的确认方法：

- 在 QQ 邮箱 Web 端尝试**手动写一封**新邮件发给任何人。
- 如果手动也发不出去、提示「当日发件量已达上限」之类的字样 → 实锤就是日配额。
- 等到**第二天北京时间 0:00 之后**，配额会重置。

如果你已经反复确认是这个原因，处理方式只有两条：

1. **短期**：用第二个 QQ 邮箱轮流发（但风控会更敏感，不推荐长期用）。
2. **长期**：上 Resend 或买域名后接 Cloudflare Email Routing。
   👉 这部分属于另一篇专题课的内容，你可以搜索 [《第 06 篇 启用邮箱登录 Resend》](./06-enable-email-login-with-resend.md) 学习，这里不展开讲解。

---

### Step 6：收件人侧检查

如果 Step 2 已发送里**能**看到，那邮件确实出去了，问题在收件方：

| 检查项 | 怎么做 |
|---|---|
| 收件方的**垃圾邮件**文件夹 | 让对方翻一下 |
| 收件方的**广告邮件** / **订阅邮件** 分类 | 让对方翻一下 |
| 收件方的邮箱**收件规则** | 让对方看下有没有把你设过滤 |
| 收件方是企业邮箱 / Gmail | 个人 QQ 邮箱发到企业邮箱很容易直接进垃圾箱，因为缺 SPF/DKIM |

最后一项是 QQ 邮箱发件最致命的弱点：**没有自定义域名，SPF/DKIM 是 QQ 默认的，企业邮箱/Gmail 评分会偏低**。

## 3. 验证步骤：你怎么知道问题真的解决了？

```bash
# 1. 服务端启动，看终端日志
pnpm dev

# 2. 触发一次发送
# 浏览器打开 http://localhost:3000，点登录，输入测试邮箱

# 3. 三件事都要满足：
# ✅ 终端没有任何 nodemailer 错误日志
# ✅ QQ 邮箱「已发送」里能看到这封新邮件
# ✅ 收件人的「收件箱」（不是垃圾箱）里能看到
```

三个都打勾，才算修好。

## 4. 常见坑

| 坑 | 症状 | 解法 |
|---|---|---|
| `SMTP_PASS` 填了 QQ 登录密码而不是授权码 | 错误日志 `535 Login Fail` | 去 Step 3 拿授权码 |
| `SMTP_PORT=587` 用了 STARTTLS 但 `SMTP_SECURE=true` | 连接握手失败 | 改成 `SMTP_PORT=465` 且 `SMTP_SECURE=true`（推荐组合） |
| 国内云主机出口封了 25 端口 | `Connection timeout` | 用 465 或者把发件机器换到能出外网的环境 |
| `MAIL_FROM` 用了别的邮箱地址 | 直接被对方服务器拒收（FROM 域名和实际发件人不一致） | `MAIL_FROM` 必须 = `SMTP_USER`，不要写别的 |
| 同一个测试邮箱反复触发 1 小时内 10+ 次 | 一开始能收，后来收不到 | QQ 反垃圾静默屏蔽，换收件人/等 1~2 小时 |
| QQ 邮箱开了「**安全登录**」/「**独立密码**」 | 授权码看着没问题但就是 `535` | 设置里关掉独立密码，再重新生成授权码 |

## 5. 什么时候应该放弃 QQ SMTP 直接上正式方案

如果你出现下面任一情况，**别继续在 QQ 上挣扎了**：

- 一天要发超过 30 封（接近 QQ 免费日上限了）
- 收件人是企业邮箱 / Gmail，进垃圾箱概率高
- 你已经买了域名，没理由不接 Resend 或自己发件域

## 一句话总结

> **晚上发不出去，先打开 QQ 邮箱看「已发送」。**
> 看得到 = 收件人那边的问题；看不到 = QQ 这边拦了（限额 / 风控 / 授权码）。
> 把这一步先确认了，再决定要不要换方案。
