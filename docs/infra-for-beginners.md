# 第 01 篇｜把你的网站第一次上线：小白也能看懂的全流程手册

> 适合人群：完全没接触过服务器 / 数据库 / 域名 / 部署的人  
> 目标：**看完后你知道每个东西是什么、为什么需要它、先注册哪个账号、每一步做完会得到什么**  
> 本篇不要求你会写代码，只要求你愿意照着一步一步点。

---

## 先说结论：你的网站上线，一共要搞定 5 个角色

把这 5 个角色记住，你后面所有操作都不会迷路：

1. **GitHub** —— 存代码
2. **Vercel** —— 让代码变成网站
3. **Neon** —— 存数据（数据库）
4. **Cloudflare** —— 买域名、管域名指向哪
5. **Resend** —— 发邮件（比如登录验证码）

你可以把它们理解成开一家店：

| 现实世界 | 网站世界 |
|---|---|
| 仓库 | GitHub |
| 店铺 | Vercel |
| 档案柜 / 账本 | Neon 数据库 |
| 门牌号 / 路牌 | Cloudflare 域名 |
| 快递员 | Resend 邮件 |

如果你只记住一句话：

> **GitHub 存代码，Vercel 跑网站，Neon 存数据，Cloudflare 管域名，Resend 发邮件。**

那这篇文章就成功一半了。

---

## 第一章：先搞明白“上线”到底是什么意思

很多人本地开发时，会在终端里运行：

```bash
pnpm dev
```

然后浏览器打开：

```text
http://localhost:3000
```

这时候你能看到网站，就会误以为：

> “网站已经做好了。”

其实不是。

### `localhost` 是什么？

`localhost` 的意思是：

> **我这台电脑自己。**

也就是说，只有你自己的电脑能访问这个地址。别人访问不到。

如果你把链接发给朋友：

```text
http://localhost:3000
```

朋友点开只会失败。

因为那个地址不是在互联网里，而是在**你自己电脑里面**。

### 那“上线”到底是什么？

上线的本质就是：

> **把你电脑里能跑的网站，搬到一台 24 小时开机、所有人都能访问的电脑上。**

那台电脑，就是服务器。

---

## 第二章：服务器到底是什么？

### 最白话的理解

服务器本质上也是一台电脑，只不过：

- 不是放在你家里
- 不是你平时办公的电脑
- 它在机房里
- 24 小时不断电
- 有公网地址
- 别人能通过互联网访问它

你可以把它理解成：

> **你的网站真正住的房子。**

你自己的电脑只是装修工地，服务器才是正式营业的门店。

### 如果没有服务器会怎样？

如果没有服务器：

- 你的网站只能在你自己电脑上看
- 你电脑一关机，网站就没了
- 别人永远访问不到

所以：

> **服务器解决的是“让别人也能打开你的网站”这个问题。**

---

## 第三章：数据库到底是什么？

数据库就是：

> **帮网站长期记住东西的地方。**

比如你的网站可能需要记住：

- 用户是谁
- 用户邮箱
- 用户登录状态
- 文章内容是什么
- 谁学到了第几课
- 谁提了反馈

如果没有数据库：

- 用户注册完，刷新一下就忘了
- 文章没法存
- 登录没法记住
- 后台数据不存在

### 数据库解决什么问题？

数据库解决的是：

> **网站需要长期保存和查询数据**

你可以把它理解成：

> **网站的大脑 + 档案柜。**

---

## 第四章：服务器和数据库是什么关系？

这是最容易让小白混乱的点。

### 一句话关系

- **服务器负责干活**
- **数据库负责记忆**

### 流程图

```text
用户打开网站
   ↓
服务器接到请求
   ↓
服务器去数据库里拿数据
   ↓
服务器把结果组装成页面
   ↓
返回给用户
```

### 类比

| 角色 | 类比 |
|---|---|
| 服务器 | 厨房 / 厨师 |
| 数据库 | 冰箱 / 仓库 |

厨师负责做菜，但原材料要从仓库里拿。

所以：

> **服务器不是数据库，数据库也不是服务器。**

---

## 第五章：域名是什么？

域名就是：

> **你网站的门牌号 / 店招。**

比如：

- `baidu.com`
- `github.com`
- `chaojigeti.com`

### 如果没有域名会怎样？

你的网站可能只有一串很难记的地址：

```text
34.120.123.88
```

这对普通人完全不友好。

所以域名解决的是：

> **让人类能记住和输入你的网站地址。**

---

## 第六章：Cloudflare 是什么？

Cloudflare 不是服务器，也不是数据库。

Cloudflare 更像：

> **你网站门口的前台 / 保安 / 导航系统 / 加速器。**

它主要负责：

### 1. 管理域名解析
当有人访问：

```text
chaojigeti.com
```

Cloudflare 会告诉浏览器：

> 这个域名应该去找哪台服务器

### 2. 加快访问速度
Cloudflare 在全球有很多节点，能让用户离你的网站更近一点。

### 3. 提供 HTTPS 和安全
比如网页上的小锁头，很多时候就是 Cloudflare 或部署平台自动帮你处理的。

### 4. 有时也能顺便帮你托管网页
Cloudflare Pages 还能直接帮你部署前端项目。

### 用最简单的话总结

> **Cloudflare 主要负责“域名怎么找到网站”以及“访问更安全更快”。**

---

## 第七章：Vercel 是什么？

Vercel 是一个专门用来部署前端 / Next.js 网站的平台。

你可以把它理解成：

> **帮你把代码变成一个别人能打开的网站的托管平台。**

### 它解决什么问题？

如果不用 Vercel，你自己买服务器就要处理：

- 怎么装 Node.js
- 怎么启动项目
- 怎么让它一直运行
- 怎么配 HTTPS
- 怎么自动更新代码
- 怎么回滚版本

Vercel 把这些都包起来了。

你只需要：

1. 把代码放到 GitHub
2. 让 Vercel 连 GitHub
3. 点一下 Deploy

它就帮你部署。

### 所以 Vercel 是什么？

> **Vercel 是“跑网站的地方”。**

---

## 第八章：GitHub 是什么？

GitHub 的作用不是“上线网站”，而是：

> **存代码，记录版本。**

你可以把它理解成：

> **代码仓库 + 版本历史 + 协作平台。**

### 为什么需要它？

因为现在大多数部署平台（Vercel、Cloudflare Pages）都默认这样工作：

```text
你把代码推到 GitHub
     ↓
Vercel 看到 GitHub 更新
     ↓
自动重新部署
```

所以 GitHub 是整个流程的入口。

### GitHub 解决什么问题？

- 代码备份
- 版本回退
- 多设备同步
- 自动部署的触发源

### 一句话

> **GitHub = 存代码的仓库。**

---

## 第九章：Neon 是什么？

Neon 是一个云端 PostgreSQL 数据库服务。

这句话对小白来说没意义，我们换成白话：

> **Neon 是“帮你托管数据库的地方”。**

你不用自己搭数据库，不用自己装 PostgreSQL，不用管磁盘，不用备份。

你只需要注册，然后它给你一串连接地址，像这样：

```text
postgresql://用户名:密码@主机名/数据库名
```

你的程序拿这串地址，就能连上数据库。

### 为什么不直接用 SQLite？

因为 SQLite 更适合：

- 本地开发
- 单机实验
- 临时小项目

一旦上线到云平台，SQLite 的问题是：

- 它是本地文件
- 文件不适合云函数/边缘环境长期持久化
- 并发能力差
- 多实例不好搞

所以生产环境更推荐：

> **Postgres（比如 Neon / Supabase）**

### 一句话

> **Neon = 给你一个现成的线上数据库。**

---

## 第十章：Resend 是什么？

Resend 是一个发邮件的服务。

它解决的问题是：

> **你的网站要给用户发邮件，但你不想自己搭邮件服务器。**

比如：

- 发登录验证码
- 发欢迎邮件
- 发重置密码邮件
- 发通知邮件

### 为什么不能自己直接发？

因为“发邮件”看起来简单，实际上很麻烦：

- 要处理垃圾邮件规则
- 要配 SPF / DKIM / DMARC
- 要控制送达率
- 要避免被收件箱拦截

Resend 帮你把这些处理掉。

### 一句话

> **Resend = 帮你发邮件的快递员。**

---

# 第十一章：这 5 个东西的关系图（最重要）

记住这张图：

```text
用户
 ↓
域名（比如 chaojigeti.com）
 ↓
Cloudflare（负责把域名指到正确地方 + 加速 + HTTPS）
 ↓
Vercel（真正运行你的网站代码）
 ↓
Neon（存数据库数据）

如果要发邮件：
Vercel 里的后端代码 → Resend → 用户邮箱
```

### 这张图翻译成人话就是：

- **用户先访问你的域名**
- **Cloudflare 帮他找到网站真正住的地方**
- **Vercel 负责把网页跑出来**
- **Vercel 再去 Neon 拿数据**
- **如果要发验证码，就让 Resend 帮你发**

这就是一个现代网站最小但完整的结构。

---

# 第十二章：为什么不直接自己买服务器？

当然可以直接买服务器，比如阿里云 ECS、腾讯云轻量服务器。

但对新手来说，直接买服务器会立刻遇到这些问题：

- 我买 1 核还是 2 核？
- Ubuntu 是什么？
- 要不要装 Node？怎么装？
- 怎么启动项目？
- 怎么让它开机自动跑？
- 怎么配 HTTPS？
- 怎么配域名？
- 怎么配数据库？
- 崩了怎么重启？

这些不是“不会写代码”的问题，而是“不会运维”的问题。

### 所以为什么推荐 Vercel + Neon + Resend + Cloudflare？

因为它们把复杂度拆开，并且每个都只做自己最擅长的部分：

| 平台 | 只负责什么 |
|---|---|
| GitHub | 存代码 |
| Vercel | 跑网站 |
| Neon | 存数据 |
| Cloudflare | 域名 / DNS / 加速 |
| Resend | 发邮件 |

这套组合的核心优势是：

> **你不用先学会运维，才能上线产品。**

这和你做「超级个体」这个产品的价值观是一致的。

# 第十三章：小白第一次正确的顺序是什么？

这是最重要的一章。

## 第 0 步：先别急着部署

先把这篇文章看懂，知道 5 个角色分别负责什么。

你现在已经做到这一步了。

---

## 第 1 步：先注册 5 个账号（只是注册，不做复杂配置）

顺序按这个来：

### 1）GitHub
作用：存代码

- 访问：<https://github.com>
- 点击：**Sign up**
- 用邮箱注册
- 用户名建议：以后公开项目你也不尴尬的名字
- 建议立刻打开 2FA（双重验证）

你注册完之后，得到的是：

> 一个 GitHub 账号（以后用来存代码）

---

### 2）Vercel
作用：部署网站

- 访问：<https://vercel.com>
- 点击：**Start Deploying** 或 **Sign Up**
- 直接选：**Continue with GitHub**
- 用刚才的 GitHub 授权

你注册完之后，得到的是：

> 一个 Vercel 账号（以后它会帮你把 GitHub 上的代码变成网站）

---

### 3）Neon
作用：数据库

- 访问：<https://neon.tech>
- 点击：**Sign up**
- 直接用 GitHub 登录最快
- 登录后创建一个 Project，名字随便，比如：

```text
super-solo-prod
```

创建完之后，Neon 会给你：

- 一个数据库实例
- 一串连接地址（connection string）

类似这样：

```text
postgresql://用户名:密码@主机/数据库名?sslmode=require
```

这串地址以后要放进环境变量里。

你注册完之后，得到的是：

> 一个线上数据库 + 一串连接地址

---

### 4）Cloudflare
作用：买域名、管域名解析、加速

- 访问：<https://cloudflare.com>
- 点击：**Sign Up**
- 用邮箱注册

注册完之后先什么都不用配，记住：

> 以后你会在这里买域名，并把域名指到 Vercel。

---

### 5）Resend
作用：发验证码邮件

- 访问：<https://resend.com>
- 点击：**Sign Up**
- 最好用 GitHub 登录

注册完之后现在也先不用做复杂配置。

记住：

> 以后登录验证码、通知邮件都从这里发。

---

## 第 2 步：把代码放到 GitHub

现在假设你已经在本地有项目了。

在项目根目录打开终端：

```bash
git init
git add .
git commit -m "init"
```

然后去 GitHub 网页：

1. 点右上角 `+`
2. 选 **New repository**
3. 仓库名随便，比如：
   - `super-solo-web`
   - `my-first-site`
4. 先选 **Private**（别人看不到你的代码）
5. 点 **Create repository**

GitHub 会出现一段命令，把它复制回来执行：

```bash
git remote add origin https://github.com/你的用户名/仓库名.git
git branch -M main
git push -u origin main
```

### 做完会发生什么？

刷新 GitHub 页面，你就会看到你的代码已经上去了。

这一步完成后，你得到的是：

> 一个在线代码仓库（后面 Vercel 会从这里拉代码部署）

---

## 第 3 步：用 Vercel 把网站先跑起来

现在去 Vercel：

1. 进入 Dashboard
2. 点 **Add New Project**
3. 你会看到 GitHub 的仓库列表
4. 选你刚才的项目
5. 点 **Import**

### 一开始别急着接数据库

为了让第一步最简单，建议先让：

> **网站先能上线，再接数据库。**

如果你的项目已经强依赖数据库，也可以直接继续，但你会同时处理两层复杂度：
- 部署层
- 数据库层

新手更容易崩。

### Vercel 会给你什么？

部署成功后，会给你一个地址，比如：

```text
https://super-solo-web.vercel.app
```

这个地址就是你网站的临时线上地址。

别人打开它，就能访问你的网站。

这一步完成后，你得到的是：

> 一个真的能被别人访问的网站

---

## 第 4 步：再接数据库（Neon）

当网站能跑了，接下来再把数据库换成 Neon。

你现在本地如果用的是 SQLite：

```text
DATABASE_URL="file:./dev.db"
```

生产上不要继续用它。

### 为什么？

因为 SQLite 是一个本地文件。放在 Vercel / Cloudflare 这种云部署平台上不稳。

### 正确做法

把 `.env` / `.env.local` 的数据库连接改成 Neon 给你的那串：

```text
DATABASE_URL="postgresql://..."
```

然后跑 Prisma migration：

```bash
pnpm db:migrate
```

如果是第一次切库，通常流程是：

1. 改 `DATABASE_URL`
2. 跑 migration
3. 把初始内容 seed 进去

例如：

```bash
pnpm db:migrate
pnpm db:seed
pnpm db:seed:topics
```

### 这一步完成后，你得到的是：

> 网站不再依赖本地数据库文件，而是真正有了线上数据库

---

## 第 5 步：再接邮件验证码（Resend）

你现在本地开发已经可以这样：

- 输入邮箱
- 验证码直接打印到终端

生产肯定不能这样，用户要真的收到邮件。

### Resend 要做什么？

主要两步：

1. 在 Resend 后台拿 `API Key`
2. 在你的域名里验证发信域名

验证后你会得到：

- `RESEND_API_KEY`
- 一个合法发件地址，比如：
  `noreply@你的域名.com`

然后把这两个环境变量放到 Vercel：

```text
MAIL_DRIVER=resend
RESEND_API_KEY=...
MAIL_FROM=noreply@你的域名.com
```

### 做完后，你得到的是：

> 用户真的能收到验证码邮件

---

## 第 6 步：最后才是域名（Cloudflare）

当你的 `xxx.vercel.app` 临时地址已经能用，再买域名。

### 为什么不一开始就买？

因为很多新手一上来就被域名、DNS、证书搞晕，结果网站还没跑起来就放弃了。

### 正确顺序

先证明：

> 网站能在 Vercel 临时地址上打开

再买域名。

### 域名步骤

1. 去 Cloudflare
2. 进入 **Domain Registration**
3. 搜索你想要的域名，比如：
   - `chaojigeti.com`
4. 付款买下来
5. 回到 Vercel 项目 → **Settings → Domains**
6. 把域名加进去
7. 按 Vercel 指示去 Cloudflare DNS 里加记录

通常是：

- `A` 记录：
  - 主机名：`@`
  - 值：Vercel 给的 IP
- `CNAME` 记录：
  - 主机名：`www`
  - 值：Vercel 给的域名

### 这一步完成后，你得到的是：

> 一个正式可分享的品牌域名

---

# 第十四章：你最终应该长什么样？

当你全部跑通之后，你的网站结构是这样的：

```text
用户访问 https://你的域名.com
          ↓
Cloudflare 负责把域名指到 Vercel
          ↓
Vercel 运行你的网站代码
          ↓
Vercel 去 Neon 读写数据库
          ↓
如果要发验证码，Vercel 调 Resend 发邮件
```

这就是一个完整上线网站最小可用的架构。

# 第十五章：最容易卡住的地方（提前告诉你）

## 卡点 1：我不知道先注册哪个账号

答案：

1. GitHub
2. Vercel
3. Neon
4. Cloudflare
5. Resend

---

## 卡点 2：我分不清谁是服务器，谁是数据库

记住一句话：

- **Vercel 跑网站 = 服务器**
- **Neon 存数据 = 数据库**

---

## 卡点 3：我不懂为什么还要 Cloudflare

因为域名需要有一个地方管理和指路。

Cloudflare 负责：
- 买域名
- 让域名找到 Vercel
- 提供加速和 HTTPS 支持

---

## 卡点 4：我已经有 SQLite 了，为什么还要 Neon

因为 SQLite 更适合本地开发，不适合长期线上运行。

Neon 给你的是：
- 真正的线上数据库
- 持久化
- 更适合部署平台

---

## 卡点 5：我能不能不注册这么多账号

从长期看，不太行。

因为每个服务都在解决不同问题：

| 服务 | 如果省掉会怎样 |
|---|---|
| GitHub | 代码没地方托管，自动部署很麻烦 |
| Vercel | 你得自己维护服务器 |
| Neon | 你得自己搭数据库 |
| Cloudflare | 你得另找地方买域名和配 DNS |
