## 三、观察 AI 的工作过程

发送提示词后，Claude Code 不会立刻就输出代码，它会先展示一个**执行计划**，列出它准备做哪些事，并征求你的确认：

```
我会创建以下文件：
• todo.py — 主程序文件

计划实现：
- 命令行参数解析（使用 sys.argv）
- JSON 文件读写（存储任务数据）
- 四个子命令：add / list / done / delete

是否继续？
```

这里有一个重要的习惯要养成：**不要每次都直接按回车确认，先读一下执行计划。**

检查几点：
- 它准备创建的文件名和位置对不对
- 技术选型有没有超出你的预期（比如你说了用 Python，它是否真的用 Python）
- 有没有明显遗漏的功能点

确认没问题，输入 `yes` 或直接回车继续。

## 四、看 AI 生成的代码

Claude Code 会生成类似下面的 `todo.py`：

```python
import sys
import json
import os

TODO_FILE = "todos.json"

def load_todos():
    if not os.path.exists(TODO_FILE):
        return []
    with open(TODO_FILE, "r", encoding="utf-8") as f:
        return json.load(f)

def save_todos(todos):
    with open(TODO_FILE, "w", encoding="utf-8") as f:
        json.dump(todos, f, ensure_ascii=False, indent=2)

def add_task(content):
    todos = load_todos()
    task = {
        "id": len(todos) + 1,
        "content": content,
        "done": False
    }
    todos.append(task)
    save_todos(todos)
    print(f"✓ 已添加任务 #{task['id']}：{content}")

def list_tasks():
    todos = load_todos()
    if not todos:
        print("暂无任务")
        return
    for task in todos:
        status = "✓" if task["done"] else "○"
        print(f"[{status}] #{task['id']} {task['content']}")

def mark_done(task_id):
    todos = load_todos()
    for task in todos:
        if task["id"] == task_id:
            task["done"] = True
            save_todos(todos)
            print(f"✓ 任务 #{task_id} 已标记为完成")
            return
    print(f"未找到任务 #{task_id}")

def delete_task(task_id):
    todos = load_todos()
    original_count = len(todos)
    todos = [t for t in todos if t["id"] != task_id]
    if len(todos) < original_count:
        save_todos(todos)
        print(f"✓ 任务 #{task_id} 已删除")
    else:
        print(f"未找到任务 #{task_id}")

def main():
    if len(sys.argv) < 2:
        print("用法：python todo.py <命令> [参数]")
        print("命令：add <内容> | list | done <编号> | delete <编号>")
        return

    command = sys.argv[1]

    if command == "add":
        if len(sys.argv) < 3:
            print("请输入任务内容")
        else:
            add_task(sys.argv[2])
    elif command == "list":
        list_tasks()
    elif command == "done":
        if len(sys.argv) < 3:
            print("请输入任务编号")
        else:
            mark_done(int(sys.argv[2]))
    elif command == "delete":
        if len(sys.argv) < 3:
            print("请输入任务编号")
        else:
            delete_task(int(sys.argv[2]))
    else:
        print(f"未知命令：{command}")

if __name__ == "__main__":
    main()
```

代码生成后，先不要运行，花 2 分钟读一下。

**你应该能回答这几个问题：**
- 任务数据存在哪里？（`todos.json`）
- `add_task` 函数做了什么？（把新任务追加到列表并保存）
- `mark_done` 是怎么找到对应任务的？（通过 `id` 字段匹配）

如果这三个问题你能回答，说明代码你基本读懂了。这就是第 04 篇说的"保持代码可读"——你不需要自己能写出来，但你需要能读懂。

## 五、运行，遇到第一个问题

来运行试试：

```bash
python todo.py add "学习 VibeCoding"
python todo.py add "完成第一个项目"
python todo.py list
```

理想情况下，你会看到：

```
✓ 已添加任务 #1：学习 VibeCoding
✓ 已添加任务 #2：完成第一个项目
[○] #1 学习 VibeCoding
[○] #2 完成第一个项目
```

如果一切正常，试试完成和删除：

```bash
python todo.py done 1
python todo.py list
python todo.py delete 2
python todo.py list
```

---

但很多时候，你可能会遇到一个问题：

**问题场景：删除任务后，再添加新任务，ID 会出现重复。**

比如你有任务 #1、#2、#3，删掉 #2，再添加新任务，新任务会被标记为 #3——和现有的 #3 重复了。

这是 AI 生成代码中常见的逻辑漏洞。`add_task` 函数里用 `len(todos) + 1` 来生成 ID，删除任务后列表变短，下一个 ID 就会和已有任务冲突。

**不要自己改代码，把这个问题告诉 AI：**

```
发现一个 Bug：删除任务后，再添加新任务会出现 ID 重复的问题。
比如任务列表是 #1 #2 #3，删除 #2 后，新添加的任务 ID 会变成 #3，
和已有任务冲突。

请修复这个问题，ID 应该始终递增，不受删除操作影响。
```

---

## 六、观察 AI 如何修复 Bug

AI 收到 Bug 描述后，会分析原因并给出修复方案。通常它会把 ID 生成逻辑改为：

```python
def add_task(content):
    todos = load_todos()
    # 修复：取现有最大 ID + 1，而不是用列表长度
    next_id = max((t["id"] for t in todos), default=0) + 1
    task = {
        "id": next_id,
        "content": content,
        "done": False
    }
    todos.append(task)
    save_todos(todos)
    print(f"✓ 已添加任务 #{task['id']}：{content}")
```

修复方案很合理：找到现有任务中最大的 ID，在此基础上 +1。即使删除了中间的任务，新 ID 也永远不会重复。

**验证修复：**

```bash
python todo.py add "任务A"
python todo.py add "任务B"
python todo.py add "任务C"
python todo.py delete 2
python todo.py add "新任务"
python todo.py list
```

应该看到新任务的 ID 是 #4，而不是 #3。

这个调试流程，就是第 04 篇说的"失败是正常的"——发现问题、描述清楚、AI 修复、验证结果，一个完整的闭环。

## 七、主动提出改进需求

**需求三：添加任务数量统计**

```

```

## 八、项目复盘：哪些步骤是你真正控制的

做完这个项目，回头看一下，在整个过程中，你真正做了什么：

| 步骤             | 谁做的 | 你的具体工作                   |
| ---------------- | ------ | ------------------------------ |
| 确定功能范围     | **你** | 决定做哪四个功能，存 JSON      |
| 写代码           | AI     | —                              |
| 读代码、理解逻辑 | **你** | 确认 3 个问题能回答            |
| 运行测试         | **你** | 执行命令，观察输出是否符合预期 |
| 发现 Bug         | **你** | 发现 ID 重复的问题             |
| 描述 Bug         | **你** | 清晰地把问题描述给 AI          |
| 修复 Bug         | AI     | —                              |
| 验证修复         | **你** | 按步骤重现问题，确认修复生效   |
| 提出改进需求     | **你** | 决定加时间、筛选、统计         |

**规律：** 所有"决定"类的工作都是你做的，所有"生产"类的工作是 AI 做的。你的价值在于判断和决策，AI 的价值在于执行和生产。

这印证了第 04 篇的核心原则：**你是导演。**

## 九、给第一次体验的三点总结

**第一点：提示词要具体，不要抽象**

"帮我做一个待办应用"和"帮我做一个命令行待办应用，支持 add/list/done/delete 四个命令，数据存在 todos.json"，AI 给出的代码质量完全不同。越具体，越省来回修改的时间。

**第二点：遇到 Bug 要描述现象，而不是猜原因**

"ID 生成有 Bug"是猜原因，AI 可能往错误方向修。"删除任务后再添加，ID 会和已有任务重复，比如删掉 #2 再添加，新任务 ID 会是 #3" 是描述现象，AI 能精准定位。

**第三点：每次修改后都要验证**

不要连续让 AI 改几个地方然后统一测试，容易搞不清楚是哪一步引入了新问题。改一个，跑一下，确认没问题再改下一个。

## 扩展练习：三个方向继续探索

如果你觉得这个项目太简单，可以挑一个方向继续深入：

**方向一：加上优先级**  
给任务加高/中/低优先级，`list` 按优先级排序，`add` 命令支持 `--priority high` 参数。

**方向二：多项目支持**  
支持多个待办列表，类似 `todo --project work add "开周会"` 和 `todo --project personal add "买菜"`，数据分开存储。

**方向三：改成 Web 版**  
用 Flask 把这个 CLI 应用改成一个简单的 Web API，配一个 HTML 前端页面。这就涉及到前后端分离了——正好是后面几篇实战课的内容。
