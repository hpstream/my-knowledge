# 写作原则（课程内容三分法）

> 这是「超级个体」站点写文章前必须先对齐的原则。
> 我（Claude）以后审核或写作任何文章前，会按这份原则检查。
> 用户后续的任何写作请求，默认套这套规则；除非用户明确说"这次不按这个来"。

## 1. 课程的三种类型

站点的内容分三类，**目的、读者状态、写法都不同**，不要混着写。

### 1.1 基础课程

- **目的**：普及基础概念，把读者从"完全不懂"带到"听得懂别人在说什么"。
- **写法**：简单、通俗易懂、少行话。能用大白话就不要用专业术语；非用不可的术语，第一次出现要解释。
- **不做**：不要在这里塞实操步骤、不要展开讲专题课/实战课里的具体操作。
- **遇到需要展开的内容**（属于专题课/实战课范围的）：
  > "👉 这部分属于专题课的内容，你可以搜索《xxx》专题课程学习，这里不展开讲解。"
  - 用这种"指路而非展开"的句式。
  - **不要**在基础课里贴大段代码、贴长配置、走完整流程。

### 1.2 专题课

- **目的**：解决一个具体的**卡点问题**。读者已经知道这件事是什么，但卡住了。
- **写法**：以**实操**为主线。明确"读完能解决什么问题"，按步骤推进。
- **结构建议**：
  1. 卡点描述：什么场景、什么症状
  2. 直接给可行的解决方案 / 推荐路径
  3. 一步步操作（命令、配置、代码）
  4. 验证：怎么确认问题真的解决了
  5. 常见坑 + 怎么绕过
- **范围**：一篇专题课聚焦**一个**卡点，不要做综述。

### 1.3 实战课

- **目的**：教读者**从零干一个完整的项目**。
- **写法**：项目驱动。从空项目出发，每一步都对应一个可见的成果，最后是一个能跑/能上线的东西。
- **结构建议**：
  1. 项目目标和最终长什么样（先看终点）
  2. 技术选型与原因
  3. 分阶段实施（每阶段都要有"完成态"）
  4. 部署/上线
  5. 后续可扩展方向

## 2. 跨类型引用规则

- 基础课程 → 提到专题/实战课内容时，**只指路，不展开**。
  推荐句式：
  > "你可以搜索《xxx》专题课程学习，这里不展开讲解。"
- 专题课 → 提到基础概念时，可以**一句话带过**并指向基础课程：
  > "（背景知识可参考基础课程《xxx》）"
- 实战课 → 既可以指路基础课程，也可以指路专题课。

## 3. 审核 checklist（我每次帮你审稿前自检）

- [ ] 这篇内容到底属于三类里的哪一类？说得清楚。
- [ ] 风格匹配吗？基础课是不是被写成了专题课（堆代码）？专题课是不是写成了综述？实战课是不是停在了概念没真的搭起来？
- [ ] 基础课里有没有跨类型展开？要不要换成"指路"。
- [ ] 专题课的"卡点"是不是聚焦在一个问题？
- [ ] 实战课有没有最终的可交付产物？
