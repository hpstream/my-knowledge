## 开篇：为什么有人用 AI 越用越顺，有人越用越乱

同样是用 Claude Code，两个人的体验可能天壤之别。

A 每天用 AI 交付功能，项目代码整洁，需求按时完成，偶尔遇到复杂问题也能和 AI 一起拆解解决。

B 用了两周就放弃了。他的问题是：AI 给的代码时好时坏，有时候改了一个地方又冒出三个新问题，整个项目越来越难维护，最后他说"AI 不靠谱，还是自己写吧"。

他们用的是同一款工具，同一个模型。

差距不在工具，在**心智模型**。

A 把 AI 当成一个需要被管理的协作者，他知道 AI 能做什么、不能做什么，知道什么时候该信任它、什么时候必须亲自把关。B 把 AI 当成一个神奇的黑盒，期待输入需求、输出完美代码，一旦结果不对就归咎于工具本身。

这篇文章讲的就是 A 和 B 之间的那个差距——VibeCoding 的核心心智模型。

## 一、你是导演，AI 是演员

VibeCoding 中最重要的一个认知：

> **你的角色是导演，不是观众，也不是龙套。**

导演不亲自上台表演，但导演决定：这场戏要讲什么故事、每个演员该在哪里站、哪条路走错了要重拍。

AI 是演员——执行力强，能快速"表演"出你描述的场景，但它不会主动理解你内心真正想要什么，也不会在你描述不清时自动纠偏，更不会在演完之后主动告诉你哪里演得不对。

### 导演的三项职责

**1. 明确意图（给方向）**

演员需要知道自己在演什么。AI 需要知道你真正想要什么。

这不是说你要写出完美的需求文档，而是说：你对自己想要的结果，要有足够清晰的认知。

一个糟糕的导演会说："随便演个好看的"。一个好导演会说："这场戏要表现出主角内心的挣扎，他在犹豫要不要开口，但最终还是沉默了。"

同样道理：

```
❌ 糟糕：帮我写一个用户管理模块

✅ 好的：帮我写用户管理模块，需要支持：
   - 用户注册（邮箱+密码）
   - 登录后返回 JWT token，有效期 7 天
   - 用户信息查询（仅本人可查）
   - 技术栈：Node.js + Express + PostgreSQL
```

**2. 审查结果（把关质量）**

演员演完一条，导演要看回放，判断这条能不能用。AI 生成完代码，你要看代码，判断逻辑对不对、有没有安全问题、是否符合项目规范。

这一步很多人省略了。他们看到 AI 洋洋洒洒输出了几百行代码，心里觉得"应该没问题吧"，直接粘贴运行。结果跑是能跑，但里面藏着各种隐患，等到上线才暴露。

**导演不需要每帧都亲自画**，但需要知道好画面和坏画面的区别。你不需要逐行审查每个函数，但你需要能判断：这段逻辑对不对，这个设计合不合理。

**3. 决策方向（掌控全局）**

拍电影过程中会遇到各种突发情况：演员临时换角、场景受限、预算超支。导演要做的是在约束条件下做出最优决策，而不是被每一个局部问题绊住。

VibeCoding 也一样。AI 有时候会走偏，给出一个看起来能解决问题但方向不对的方案。这时候你要能识别出"这条路走下去会有问题"，果断叫停，重新给方向。

## 二、"信任但验证"原则

这是 VibeCoding 的核心工作原则，来自冷战时期里根总统与苏联谈判的一句话："Trust, but verify."

对 AI 生成的代码，应该采取同样的态度：**默认信任它能完成任务，但对关键结果必须验证。**

### 什么需要验证，什么可以直接用

**可以较高信任（但仍需运行测试）：**
- 主流语言的基础语法（Python、JavaScript、TypeScript 的核心特性）
- 常见算法的实现（排序、查找、字符串处理）
- 标准库的用法（Python 内置模块、Node.js 核心 API）
- 样板代码（配置文件、脚手架结构、标准中间件）

**必须人工仔细审查：**
- 业务逻辑的正确性（AI 不了解你的业务规则）
- 第三方库的 API 用法（版本差异大，幻觉高发区）
- 权限控制和安全相关代码（错了就是漏洞）
- 数据库操作（错误的查询可能导致数据丢失）
- 涉及金额、计数等精确计算的逻辑

### 验证的三种方式

**方式一：运行跑通**

最基础的验证。至少保证代码能运行，不报语法错误。这一步可以让 AI 帮你写测试用例一起跑。

**方式二：逻辑审查**

读代码，逐段理解逻辑。不需要逐行看，关注：
- 主流程是否符合预期
- 边界情况有没有处理（空值、异常输入）
- 有没有明显的性能问题（比如循环里做了数据库查询）

**方式三：让 AI 自审**

把 AI 生成的代码再喂回给它，让它找问题：

```
请审查上面这段代码，重点检查：
1. 是否有安全漏洞（SQL 注入、XSS、未授权访问）
2. 边界情况是否处理完整
3. 有没有潜在的性能问题
如果有问题请直接指出并给出修复方案。
```

这个技巧非常实用，AI 在审查模式下往往能发现它在生成模式下遗漏的问题。

## 三、增量迭代：小步快跑而不是一次成型

这是新手最常犯的错误之一：

> 把需求一次性全部告诉 AI，期望它输出一个完整的、可直接使用的系统。

这种做法几乎注定失败。

原因有三：
1. 需求描述越长，AI 理解出错的概率越高
2. 一次生成的代码越多，出问题时越难定位根因
3. AI 在长任务中更容易"漂移"，早期的约定在后期被遗忘

### 正确的方式：像搭积木一样

把功能拆成尽可能小的单元，一个一个地让 AI 完成，每完成一个就验证一个。

**例子：做一个用户登录功能**

❌ 错误做法（一次性）：
```
帮我实现完整的用户登录功能，包括：注册、登录、JWT token 生成、
token 刷新、密码重置、邮件发送、图形验证码、登录失败次数限制...
```

✅ 正确做法（逐步推进）：

```
第一步：先帮我建 User 数据库表，字段：id、email、password_hash、created_at
```
→ 验证建表脚本
```
第二步：实现注册接口，接收 email 和 password，密码用 bcrypt 加密存入数据库
```
→ 运行测试注册
```
第三步：实现登录接口，校验密码，登录成功返回 JWT token，有效期 7 天
```
→ 测试登录流程
```
（后续再逐步加 token 刷新、密码重置等）
```

每一步都小到可以在 5 分钟内验证完。出了问题范围小，好定位。

### 增量迭代的节奏

```
描述一个小需求
    ↓
AI 生成代码
    ↓
运行 + 简单审查
    ↓
有问题？→ 告诉 AI 具体哪里不对，继续修
没问题？→ 描述下一个小需求
```

这个循环越快越好。理想状态是每 10~15 分钟完成一个小单元，不断积累进展。

## 四、失败是正常的：调试也是 VibeCoding 的一部分

一个让很多新手沮丧的真相：

> **VibeCoding 不是"说一句话，完美代码出来"。它通常需要多轮迭代和调试。**

Karpathy 本人在描述 VibeCoding 时也提到：他会接受错误，只要能运行通过测试就行，甚至不会细看错误是什么。当然，这是一个极端熟练的工程师说的话——他能快速判断哪些错误不影响最终结果。

对于普通使用者，更实用的心态是：

**把报错看成对话的一部分，而不是失败的信号。**

### 遇到报错时的标准流程

```
AI 生成代码 → 运行报错
                  ↓
         把完整错误信息给 AI
         "运行后报了这个错误：[粘贴错误信息]
          请帮我分析原因并修复"
                  ↓
         AI 给出修复方案
                  ↓
         再次运行验证
```

不需要自己先分析报错，直接把错误信息丢给 AI 是效率最高的方式。但有一点：**把完整的错误信息给它，不要只给最后一行**。很多错误的根因在调用栈的中间位置。

### 什么时候该自己查，而不是继续问 AI

如果同一个问题来回修了三四次还没解决，不要继续让 AI 猜。这时候需要：

1. **缩小范围**：写一个最小复现示例，确认问题出在哪一层
2. **查官方文档**：特别是涉及第三方库的问题，文档永远比 AI 更可靠
3. **换个角度提问**：不要问"为什么报错"，改问"这个功能最简单的实现方式是什么"，让 AI 从头来过

有时候最快的解决方法是放弃当前路径，换一种实现思路。

## 五、四个心智模型的实际应用

把以上四个原则合在一起，看一个完整的实际场景。

**场景：你要给一个内部工具加一个数据导出功能，把表格数据导出为 Excel。**

**心智模型一（你是导演）**：先想清楚功能边界
- 导出哪些字段？所有字段还是部分字段？
- 文件名怎么命名？
- 是前端直接下载，还是后端生成后发邮件？
- 有没有数据量上限？

想清楚之后再去和 AI 对话，而不是直接说"帮我做个导出 Excel 功能"然后期待 AI 替你想清楚这些问题。

**心智模型二（增量迭代）**：把任务拆开
- 第一步：先把后端生成 Excel 文件的逻辑跑通
- 第二步：再做前端的下载按钮和请求逻辑
- 第三步：最后处理大数据量的分页导出

**心智模型三（信任但验证）**：关注风险点
- 这个功能涉及数据权限——要验证用户只能导出自己有权限看到的数据
- 大数据量导出可能导致服务器内存问题——要测试一下边界情况

**心智模型四（失败是正常的）**：遇到问题不慌
- Excel 库的 API 不熟悉？报错了直接把错误信息给 AI
- 生成的文件在 Mac 上打开正常，Windows 上乱码？告诉 AI 这个具体现象，让它定位原因

## 六、一个容易被忽视的原则：保持代码可读

VibeCoding 有一个特有的陷阱：**AI 生成的代码能跑，但你自己看不懂。**

这在短期内不是问题，但会慢慢变成一个越来越大的问题：

- 你无法判断 AI 下一次修改的代码是否正确
- 出了 Bug 你不知道从哪里找
- 项目里出现了越来越多"能跑但不知道怎么工作"的代码

**解决方法：把代码可读性作为验收标准之一。**

每次 AI 生成代码后，问自己一个问题："这段代码，我能用 2 分钟向别人解释清楚它是怎么工作的吗？"

如果不能，让 AI 加上注释，或者重写得更清晰：

```
这段代码的逻辑有些复杂，能帮我：
1. 给每个主要逻辑块加上简短注释
2. 把超过 30 行的函数拆分成更小的函数，每个函数只做一件事
```

你不需要能自己写出这段代码，但你需要能读懂它。**读懂是把关的前提。**

## 本篇小结

VibeCoding 的四个核心心智模型：

| 心智模型         | 核心要点             | 常见错误               |
| ---------------- | -------------------- | ---------------------- |
| **你是导演**     | 负责意图、审查、决策 | 完全把控制权交给 AI    |
| **信任但验证**   | 重要代码必须人工把关 | 生成完直接用，不看不测 |
| **增量迭代**     | 小步推进，每步验证   | 一次性提所有需求       |
| **失败是正常的** | 报错是对话的一部分   | 遇到报错就放弃工具     |

加一条隐含原则：**保持代码可读**——你需要能理解 AI 写的代码，否则无法有效把关。
