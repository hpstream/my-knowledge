# 第 02 篇｜从 0 开始注册 GitHub、Vercel、Neon、Cloudflare、Resend

> 适合人群：完全没注册过这些平台，不知道先去哪里、点哪个按钮的人  
> 目标：**不是把网站上线，而是把所有“上线前必须有的账号”先准备好**  
> 阅读建议：先读完《第 01 篇｜把你的网站第一次上线：小白也能看懂的全流程手册》再看本篇

---

## 先说清楚：你今天不是要“上线网站”

你今天只是要完成一件事：

> **把后面会用到的账号，先一口气注册好。**

这样等到我们真正部署的时候，你不会卡在：

- “啊？原来这里还要注册账号？”
- “邮箱没验证，先停一下。”
- “GitHub 还没开，得先去搞那个。”

所以今天的目标是：

```text
GitHub   ✅
Vercel   ✅
Neon     ✅
Cloudflare ✅
Resend   ✅
```

都准备好。

做完后，你会拥有：

- 一个存代码的地方（GitHub）
- 一个部署网站的地方（Vercel）
- 一个数据库服务（Neon）
- 一个未来买域名和配域名的地方（Cloudflare）
- 一个发邮件验证码的地方（Resend）

---

# 第 1 章：先准备一个统一的邮箱

在你开始注册前，我建议你先做一件小事：

> **后面所有平台尽量用同一个主邮箱注册。**

比如：

```text
you@example.com
```

或者你日常常用的 Gmail / Outlook / QQ 邮箱。

### 为什么？

因为以后你会收到：

- GitHub 安全提醒
- Vercel 部署通知
- Neon 数据库通知
- Cloudflare 域名续费提醒
- Resend 邮件额度提醒

如果 5 个平台 5 个邮箱，会很乱。

### 你现在要做什么？

- 选一个你长期会用的邮箱
- 确保你能登录它
- 确保你能接收验证码 / 激活邮件

如果你还没有稳定邮箱，建议：

- 国外服务多：用 **Gmail**
- 国内使用方便：用 **QQ 邮箱** 或 **Outlook**

> 只要你能长期收邮件就行，不需要一开始纠结完美方案。

# 第 2 章：注册 GitHub（存代码）

## GitHub 是干嘛的？

一句话：

> **GitHub 是存代码的仓库。**

以后你的网站代码会先放到这里，然后 Vercel 从这里拉代码去部署。

如果没有 GitHub，后面你会卡在：

- Vercel 没法自动部署
- 代码没有备份
- 版本没法回退

## 第一步：打开 GitHub

网址：

> <https://github.com>

你会看到页面右上角有 **Sign up** 或 **Create account** 按钮。

### 点击它的意义是什么？

这是在创建：

> 你的代码仓库账号

以后：
- 代码都在这里
- 项目版本历史都在这里
- 也可以邀请别人协作

## 第二步：填写注册信息

GitHub 一般会让你填写：

1. **Email**：你的邮箱
2. **Password**：密码
3. **Username**：用户名

### 这个用户名重要吗？

重要，但不用太纠结。

因为你的仓库地址以后会长这样：

```text
https://github.com/你的用户名/仓库名
```

所以建议：
- 用以后你不尴尬的名字
- 不要太随意（比如 `abc1234567890`）
- 也不用太商业（暂时你还没定品牌时）

如果以后品牌稳定了，也可以新建组织或新号，但一开始没必要追求完美。

## 第三步：邮箱验证

GitHub 会给你发一封验证邮件。

### 你要做什么？

- 打开你刚才注册用的邮箱
- 找到 GitHub 的验证邮件
- 点里面的确认链接

### 这一步为什么必须做？

因为：
- 不验证邮箱，很多功能会受限
- 以后安全提醒、密码找回都靠这个邮箱

## 第四步：建议立即做的两件事

### 1）开启 2FA（双重验证）

GitHub 很重要，因为你所有代码都在里面。建议开双重验证。

路径一般在：

```text
头像 → Settings → Password and authentication
```

你会看到 **Two-factor authentication**。

开启后，登录时除了密码，还要手机验证码或验证码 App。

### 这一步解决什么问题？

防止别人知道你密码后直接拿走你的代码仓库。

### 2）把 GitHub 语言切成你看得懂的

GitHub 目前大部分界面是英文，但只要你知道几个固定按钮就够了：

- **New repository** = 新建仓库
- **Settings** = 设置
- **Code** = 代码
- **Issues** = 问题
- **Pull requests** = 合并请求

如果你英文看不懂，不用现在学 GitHub 的所有词。你只要记住后面会用到的那几个按钮就行。

## GitHub 注册完成后，你得到了什么？

你现在得到了：

- 一个 GitHub 账号
- 一个以后专门放代码的地方

**今天先停在这里，不用急着上传代码。**

# 第 3 章：注册 Vercel（部署网站）

## Vercel 是干嘛的？

一句话：

> **Vercel 负责把 GitHub 上的代码变成一个能打开的网站。**

以后你只要 push 代码，Vercel 就能自动重新部署。

## 第一步：打开 Vercel

网址：

> <https://vercel.com>

首页一般会有：

- **Sign Up**
- **Start Deploying**
- **Continue with GitHub**

## 第二步：直接用 GitHub 登录

### 为什么推荐这样做？

因为 Vercel 最方便的方式就是：

> 让它直接连接你的 GitHub 仓库。

你不用再单独设置用户名密码，也不用以后每次手动上传代码。

### 你要点击什么？

点：

> **Continue with GitHub**

然后 GitHub 会弹出授权页面。

### 授权页面是什么意思？

它是在问你：

> “你愿不愿意让 Vercel 看见你的 GitHub 仓库，并在以后帮你部署？”

你可以理解成：

> 给 Vercel 一个“读取代码、触发部署”的许可。

**不是把你的代码公开。**

如果你 GitHub 仓库是私有的，别人依旧看不到。

## 第三步：完成初始化

登录后，Vercel 可能会问：

- 你是个人用还是团队用？
- 给你的 workspace 起个名字

### 选哪个？

一开始选：

> **个人 / Hobby / Personal**

就行。

免费版完全够你起步。

## Vercel 注册完成后，你得到了什么？

你现在得到了：

- 一个 Vercel 账号
- 它已经跟 GitHub 打通了

以后当你把代码推到 GitHub 时，Vercel 可以直接拿来部署。

# 第 4 章：注册 Neon（数据库）

## Neon 是干嘛的？

一句话：

> **Neon 给你一个线上数据库。**

你的网站以后要存：

- 用户
- 登录状态
- 文章
- 反馈
- 学习进度

这些数据不能只存在你本地电脑里，所以要用数据库。

## 第一步：打开 Neon

网址：

> <https://neon.tech>

页面一般会有：

- **Sign Up**
- **Continue with GitHub**

## 第二步：推荐直接用 GitHub 登录

### 为什么？

因为你现在已经有 GitHub 账号了，用 GitHub 登录是最快的。

这样你就少记一个密码，也更统一。

## 第三步：创建 Project

登录后，Neon 会让你创建一个数据库项目。

你会看到类似：

- **Project name**
- 选择区域（Region）
- 数据库名

### 这些是什么意思？

#### Project name
就是这个数据库项目的名字。随便起，但建议以后看得懂。

比如：

```text
super-solo-prod
```

#### Region
数据库放在哪里。

### 该怎么选？

如果你不知道怎么选，就选：

> 离你主要用户近一点的地区

如果你现在只是学习和验证：
- 选一个默认推荐区域就行
- 先别纠结优化

#### 数据库名
Neon 通常会自动给一个默认值。可以先用默认。

## 第四步：保存连接串

项目创建后，你会看到一段像这样的东西：

```text
postgresql://用户名:密码@主机名/数据库名?sslmode=require
```

这就是：

> **数据库连接地址（connection string）**

### 你要做什么？

先把它复制出来，临时保存到一个安全的地方。

以后它会放进环境变量里，比如：

```text
DATABASE_URL=postgresql://...
```

### 为什么它重要？

因为你的代码想连数据库，必须知道：

- 数据库在哪台机器
- 用哪个用户名
- 用哪个密码
- 连哪个库

连接串把这些都写在一起了。

## Neon 注册完成后，你得到了什么？

你现在得到了：

- 一个云数据库项目
- 一串数据库连接地址

# 第 5 章：注册 Cloudflare（域名和指路系统）

## Cloudflare 是干嘛的？

Cloudflare 未来会负责：

1. 买域名
2. 管域名的解析（让域名找到你的网站）
3. 提供一些加速和安全能力

## 第一步：打开 Cloudflare

网址：

> <https://cloudflare.com>

点击：

> **Sign Up**

## 第二步：注册

Cloudflare 一般只需要：

- 邮箱
- 密码

### 注册完今天要不要立刻买域名？

**不用。**

今天只是先把账号开好。

### 为什么不急着买？

因为你的网站还没上线，域名也还没有指向目标。

过早买域名不会帮你更快完成验证，反而会多一层焦虑。

等到：

- GitHub 有了
- Vercel 有了
- 网站先能在 `xxx.vercel.app` 跑起来了

再买域名最顺。

## Cloudflare 注册完成后，你得到了什么？

你现在得到了：

- 一个以后买域名和管 DNS 的账号

---

# 第 6 章：注册 Resend（发邮件）

## Resend 是干嘛的？

你的网站以后会做：

- 邮箱验证码登录
- 登录通知
- 找回密码（如果将来要做）

这些都需要发邮件。

Resend 就是帮你做这件事的。

## 第一步：打开 Resend

网址：

> <https://resend.com>

点击：

> **Sign Up**

## 第二步：推荐用 GitHub 登录

同样的理由：

- 统一
- 少一个密码
- 快

## 第三步：先创建账号，不急着验证域名

Resend 后面最麻烦的一步其实是：

> 绑定你自己的发件域名

但那一步今天还不用做。

因为它依赖：
- 你已经有正式域名
- 你已经能访问 Cloudflare DNS

所以今天只要做到：

- 账号注册成功
- 能进 Dashboard

就够了。

## Resend 注册完成后，你得到了什么？

你现在得到了：

- 一个以后用来发邮件的服务账号

- [ ] Neon 里已经有一个 Project

- [ ] Cloudflare 能正常登录
- [ ] Resend 能正常登录

只要这些都完成，今天就成功了。

# 第 8 章：你今天最容易卡住的地方

## 卡点 1：GitHub 授权 Vercel 时我不敢点

你怕的是：

> “是不是点了就把代码公开了？”

答案：**不会。**

授权只是让 Vercel 能读取你的仓库并部署。

如果仓库是 Private，别人仍然看不到。

---

## 卡点 2：Neon 里那串连接串我看不懂

完全正常。

你现在不需要理解每一段具体含义，你只需要知道：

> 这是一张“进入数据库的通行证”

以后我们会把它放进 `DATABASE_URL` 环境变量里。

---

## 卡点 3：Cloudflare 注册完没看到“买域名”按钮

没关系。

你现在不需要买域名。今天只需要账号在手。

---

## 卡点 4：Resend 里各种 Domain / API Keys 看不懂

也没关系。

今天先别碰这些。后面真正接邮件时再做。
