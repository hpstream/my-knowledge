# article/ 文章目录索引

> 从现在开始，所有新文章都放在 `article/` 下面。
> 按内容形态分两个大类：**系列文章** 和 **专题文章**。

---

## 当前目录规则

```text
article/
  系列/
    从0开始用github管理项目/
      README.md            ← 系列首页 + 大纲
      01-如何注册-github.md
      02-从0开始建立一个仓库.md
      03-如何安装git.md
      04-拉代码和提代码.md
  专题/
    （单点卡点文章放这里，比如 "QQ SMTP 晚上发不出去怎么办"）
  普通人也能做产品/
    README.md
    01-普通人也能做产品了-为什么偏偏是现在.md
    ...
```

命名格式统一为：

```text
NN-文章标题.md
```

例如：
- `01-如何注册-github.md`
- `01-普通人也能做产品了-为什么偏偏是现在.md`

## 当前大类说明

### 系列

适合放：
- **有顺序、适合连续阅读的内容**
- 像一条学习路线一样的内容
- 用户跟着走一遍能掌握一个完整能力

每个系列单独建一个文件夹，里面带一份 README 当系列首页。

### 专题

适合放：
- 解决**一个具体卡点**的单点文章
- 用户带着具体问题来，看完就走
- 不依赖前后顺序

> 判断技巧：
> 如果几篇文章之间**有明显先后依赖**（比如不学 A 就没法学 B），那就属于**系列**，不属于专题。

### 普通人也能做产品

适合放：
- 面向普通人的**系列认知文章**
- 从完全不懂到建立整体地图的内容

入口：
- [普通人也能做产品 README](./普通人也能做产品/README.md)

## 后续规则

以后每次新增文章，都同步做两件事：

1. 把文章放进合适的目录
   - 有顺序、能连成一条路线 → `系列/`，新建一个系列文件夹
   - 单点解决一个卡点 → `专题/`
2. 在这个 `article/README.md` 里补一条索引，至少写清：
   - 文章标题
   - 文件路径
   - 适合人群
   - 目标
   - 文章大纲（3-5 条）

### 文章版式要求（以后默认都按这个来）

每篇文章的结构默认统一成：

1. **标题**
2. **开头信息区**
   - 系列 / 副标题 / 标签
   - 难度 / 阅读时长 / 前置
3. **正文内容**
4. **结尾小结**
5. **几道题 / 小练习**

也就是说：
- **文章开头**要放头部信息区
- **文章结尾**要放总结和小题

这样以后你找文章，直接看这个 README 就行。
