## 当前目录规则

目前先保留一个大类：

```text
article/
  专题/
    01-如何注册-github.md
    02-从0开始建立一个仓库.md
    03-实现邮件发送功能.md
```

命名格式统一为：

```text
NN-文章标题.md
```

例如：
- `01-如何注册-github.md`
- `02-从0开始建立一个仓库.md`
- `03-实现邮件发送功能.md`

## 文章索引

### 专题

#### 01. [如何注册 GitHub](./专题/01-如何注册-github.md)
- 适合人群：第一次接触 GitHub 的新手
- 目标：完成 GitHub 账号注册，并知道后续为什么一定会用到它
- 大纲：
  1. GitHub 是什么，为什么后面要用它
  2. 打开官网开始注册
  3. 用户名、邮箱、密码怎么填
  4. 邮箱验证怎么做
  5. 注册成功后先做哪几个基础设置

#### 02. [从 0 开始建立一个仓库](./专题/02-从0开始建立一个仓库.md)
- 适合人群：已经有 GitHub 账号，但还不会自己建仓库的人
- 目标：创建第一个仓库，并理解几个关键选项
- 大纲：
  1. 什么是仓库，为什么项目要先有仓库
  2. New repository 的入口在哪里
  3. 仓库名、description、public/private 怎么选
  4. README、.gitignore、license 要不要勾
  5. 创建完后下一步做什么

#### 03. [实现邮件发送功能](./专题/03-实现邮件发送功能.md)
- 适合人群：已经有项目，但还不会把邮件发送真正接通的人
- 目标：让项目具备真实邮件发送能力，并完成基础验证
- 大纲：
  1. 邮件发送功能在项目里解决什么问题
  2. 选择哪种发送方案（SMTP / Resend）
  3. 配置环境变量
  4. 在代码里接入发送逻辑
  5. 如何验证邮件真的发出去了

## 后续规则

以后每次新增文章，都同步做两件事：

1. 把文章放进 `article/专题/`（如果你没特别说明别的大类）
2. 在这个 `article/README.md` 里补一条索引，至少写清：
   - 文章标题
   - 文件路径
   - 适合人群
   - 目标
   - 文章大纲（3-5 条）

### 文章版式要求（以后默认都按这个来）

每篇文章的结构默认统一成：

1. **标题**
2. **开头信息区**
   - 适合人群
   - 目标
   - 前提（如果有）
3. **正文内容**
4. **结尾小结**
5. **几道题 / 小练习**

也就是说：
- **文章开头**要放「适合人群 / 目标 / 前提」这类信息
- **文章结尾**可以放几道题，帮助读者检查自己有没有学会

这样以后你找文章，直接看这个 README 就行。
